## 0. 本轮变更摘要

### 0.1 权威范围（**照抄用户原话，不放宽**）
> 「台球被撞击后的滚动又感觉缺少一点，还是不够像真实台球被撞击后的滚动」

用户明确点了三样：**① 球不自转（视觉）**、**② 滚得太短、停太快**、**③ 真球是"先滑后滚"两段**。
- **① 不在本 spec 范围**（已单独派人修视觉自转）。
- **本 spec 覆盖 ② + ③。**

### 0.2 一句话概括
**把「恒定减速度」改成「速度的函数」**：高速时用**大**减速度（近似滑动摩擦）、低速时用**小**减速度（近似滚动阻力），
中间用一段 `clamp01` 线性过渡；**并保证 `a_slide == a_roll` 时与现行恒定模型逐位等价**（显式逃生舱）。

### 0.3 ★ 为什么 ② 与 ③ 是同一件事（**必须能同时解释两轮抱怨**）
| 轮次 | 用户抱怨 | 当时的模型 | 恒定模型的解释 |
|---|---|---|---|
| 上一轮 | 「滚**太久**」 | `a = 0`（**完全不减速**；且门控 `a > 0` 为假 ⇒ 整条滚阻分支被**整段跳过**） | 无任何耗散 ⇒ 永不静止（**实测 30 s 上限内未静止**） |
| 本轮 | 「滚**太短、停太快**」 | `a = 0.9`（**恒定**，且远大于真实台呢 0.05–0.15） | 全场都用"大"减速度 ⇒ 末端被**多扣**了，球在低速段被过早掐停 |
⇒ **两次抱怨不矛盾**：**恒定 `a` 的两端都不像真球** —— 一端"永不减"，另一端"全程重扣到停"。
真台球是**两段**：**先滑**（接触点滑动摩擦，大减速，能量掉得快）→ **后滚**（纯滚动阻力，小减速，慢慢蹭）。
⇒ 只调 `a` 的大小**必然**在"太久/太快"之间来回弹，**唯一出路是让 `a` 随速度变**。

## 3. 物理模型（**复核 + 可证伪形式**）

### 3.1 真球的两段（**推导，用于给量级与形状，不用于断言**）
球被**中心高度**击中 ⇒ 初始 `v = v0`、`ω = 0`（**纯滑动**）。接触点滑动摩擦 `μ_s`：
- 线减速度 `a_s = μ_s·g`；角加速度 `α = 5·μ_s·g / (2r)`
- 到**自然滚动**（`v = ω·r`）：`v_roll = (5/7)·v0`、`t_roll = 2·v0 / (7·a_s)`、`d_slide = 12·v0² / (49·a_s)`
- 之后**纯滚动**：`a_r = μ_r·g`，且 `a_r ≪ a_s`
- 量级：`μ_s ≈ 0.2 ⇒ a_s ≈ 1.96 m/s²`；`μ_r ≈ 0.01–0.03 ⇒ a_r ≈ 0.10–0.30 m/s²`
> **这些公式在本项目里只给"量级"与"形状"** —— 见 §3.4。

### 3.2 本内核采用的**近似**（规格的规范形式）
```
a(v) = a_roll + (a_slide − a_roll) · clamp01(v / v_transition)
```
- `v ≥ v_transition` ⇒ `a(v) = a_slide`（滑动段）
- `v → 0` ⇒ `a(v) → a_roll`（滚动段）
- 边界：**必须显式定义** `v_transition ≤ 0` ⇒ `a(v) = a_slide`；`v ≤ 0` ⇒ `a(v) = a_roll`（两条边界在 `a_slide == a_roll` 时返回同值 ⇒ 见 §3.3）

### 3.3 ★ **退化约束（硬要求）**
> **`a_slide == a_roll` ⇒ `a(v) ≡ that`，且与现行"恒定 `rollingDeceleration`"逐位等价。**

- **为什么是硬要求**：① 既有语义（`T32b`/`T37`/`T33` 与出厂基线）**不作废**；② 逃生舱**显式**：调参失败可一键回到恒定模型；③ 让 `T54` 成为**可判定的等价判据**（逐位比较，不是"看起来像"）。
- **逐位等价的实现要点**（实现方照做）：
  - `a(v)` 写成 `a_roll + (a_slide − a_roll) * t`（`t = clamp01(...)`）：当 `a_slide == a_roll` 时 `(a_slide−a_roll)` 恰为 `+0`，`a_roll + 0*t ≡ a_roll`（IEEE 精确）。
  - **所有**原本读 `_params.rollingDeceleration` 的 3 个调用点（§2.1）改读 `a(v)` ⇒ 退化时三者同值 ⇒ **逐步逐位一致**。
- **如何验证（含注入负对照）**：见 §5 `T54`（逐位）与 `T55`（**调用点单点性**白盒守卫）。

### 3.4 ⚠ **强声明：本实现不模拟自转**（防误读）
> 本内核**没有角速度状态 `ω`**。上面 §3.2 的 `a(v)` 是**按速度阈值的两段近似**，
> **不是**在积分转动/滑动摩擦。因此：
> - **`v_roll = (5/7)v0`、`t_roll`、`d_slide` 这些解析值不得被写成断言**（它们只解释"为什么高速段该扣得多"）；
> - **"球不自转"这条用户反馈，其视觉部分由另一单负责**；
> - 本 spec 的判据**只断言"两段的形状/单调性/退化等价/不造能/确定性"**，不断言真实转动量（见 §5 各条的**盲带**）。

### 3.5 单调性与连续性（**选连续，给理由**）
- **连续性**：`a(v)` 在 `v_transition` 处**连续**（左右极限都 = `a_slide`）。
  **理由**：硬切换（`if v ≥ vt then a_slide else a_roll`）会让**位置推进的 `v_avg` 在跨阈值那一子步跳变** ⇒ 速度曲线出现折点、且**跨阈值时刻对步长敏感**（同一物理场景在不同子步数下结果不同）；连续式让过渡只依赖**当前速度**，仍是**纯函数**。
- **单调性**：`v ↦ a(v)` 单调不减（`a_slide ≥ a_roll` 时），故 `v ↦ dv/dt` 单调 —— 判据见 §5 `T56b`。

```csharp
}
```
⇒ 19 处 `p.rollingDeceleration = a;` **一行换一行**改成 `p.SetConstantRolling(a);`。

> ⚠ **实现前必读：那 19 处**不是**都能"一行换一行"（`d8impl` 开工前实测发现）** ——
> 它们**几乎全部位于 `new PhysicsParams { … }` 的「对象初始化器」里**（如各测试文件的 `Params(...)` 辅助函数），
> 而 **C# 的对象初始化器内不能调用方法** ⇒ 必须改成**两步**：
> ```csharp
> // 旧：return new PhysicsParams { cushionRestitution = e, …, rollingDeceleration = a, };
> // 新：
> var p = new PhysicsParams { cushionRestitution = e, cushionTangentialFriction = mu,
>                             ballRestitution = 1f, ballTangentialFriction = 1f, rollingDecelerationSlide = a,
>                             rollingDecelerationRoll = a };
> p.SetConstantRolling(a);   // 恒等于上两行；保留以把"恒定档"概念单点化
> return p;
> ```
> ⇒ **机械做法**：先把初始化器里的 `rollingDeceleration = a,` 改成**两个新字段**（保证 `F2c` 的"字段齐全"要求仍然满足），
> 再在构造之后补一句 `p.SetConstantRolling(a);`（**单点化语义**）。**别指望纯文本替换**。

> ⚠ **关键区别（必须写清，否则后人会以为我们自相矛盾）**：
> `SetConstantRolling` 是**便利构造**、**只写那两个已存在的字段**，**不新增存储** ⇒ **不违反 `Q-14` (a) 的裁定**，
> 反而把"恒定档"变成**单点、具名**的概念（**铁律 16 满足**）。
> 而**旧字段 `rollingDeceleration` 是真正的第二个存储**（同一个量两种写法，必然分叉）—— **那才是被删的理由**。
> ⇒ **"加一个便利方法" 与 "删一个重复字段" 是两件性质相反的事**，不得混为一谈。

### 4.4 内核改法（**单点**）
1. 新增 `private float DecelerationAt(Vector2 v)`（**唯一的 `a(v)` 实现**）：
   ```csharp
   // a(v) = a_roll + (a_slide - a_roll) * clamp01(v / v_transition)
   // 边界：v_transition <= 0 ⇒ a_slide；speed <= 0 ⇒ a_roll（a_slide==a_roll 时两条同值 ⇒ 退化逐位等价）
   ```
2. **三个调用点**（§2.1 列出的三处：**子步内位置推进** / **TOI 后剩余时间推进** / **子步末应用**）**全部**改为 `DecelerationAt(_balls[i].velocity)`
   ⇒ **`PoolSimulator.cs` 中除 `DecelerationAt` 内部与构造缓存外，不得再出现 `_params.rollingDeceleration` 的直接读取**（由 `T55` 白盒守卫钉）。
3. **门控**（`AdvanceSubStep` 内，§2.1 已列）：`if (_params.rollingDeceleration > 0f)` ⇒ **`if (a_slide > 0f || a_roll > 0f)`**。
   - **"两段都取 0"时的行为**：门控为假 ⇒ **与历史一致**（分支整段跳过）⇒ 由 `T59` 钉。
   - ⚠ **不得**把门控写成 `&&`（那会在"只有一段非零"时错误地跳过 ⇒ `T59` 的注入负对照）。
4. **不升能**：`DecelerationAt` 返回前**必须** `Mathf.Max(0f, a)`（负的 `a_roll` 会造能）—— `T57` 钉。

## 5. 测试族（**判据续 `T54`**；每条含**盲带 + 判别力来源 + 注入式负对照**；**丙类 = 0**）

> **通用约定**：期望值一律来自**被测对象之外**，并标明来源
> （**甲** = 独立闭式/几何；**乙** = 由生产常量派生；**乙-系数选定** = 阈值/余量为选定；**丙** = 转写被测代码 = **本 spec 0 条**）。
> 新增/修改的测试文件建议：`Tests/EditMode/PoolSimulatorTwoStageRollingTests.cs`（**新文件**，避免与既有文件互相压行）。

### T54 **退化等价（硬要求）**：`a_slide == a_roll` ⇒ 与恒定模型逐位一致
- **做法**：同一初态（单球、台面中心、`v0 = MaxBallSpeed`、无段无袋空台），
  ① 用**退化档**（`a_slide = a_roll = 0.9`）跑 `N` 步；
  ② 用**旧代码路径**（`rollingDeceleration = 0.9`，即"恒定"）跑 `N` 步；
  ③ **逐步逐位比较**位置/速度（`ToString("R")`）。
- **期望值来源**：**甲**（同一算术式的等价性）+ **判定式**（逐位比较）。
- **判别力**：`a(v)` 写成查表 / 硬切换 / 三个调用点里漏改一个 ⇒ 退化档不再逐位一致 ⇒ FAIL。
- **盲带**：只覆盖**退化档**；非退化档的形状由 `T56` 承担。**漏改调用点**在退化档下**不可见**（三处同值）⇒ 由 `T55` 承担。
- **注入负对照**：把 `DecelerationAt` 的实现改成 `return a_roll * 0.999f;` ⇒ `T54` FAIL。

### T55 **单点实现守卫**（白盒）：`DecelerationAt` 是唯一读取点
- **做法**：扫 `Runtime/Physics/PoolSimulator.cs`（剔 `//` 注释），断言
  ① 存在 `DecelerationAt(`；
  ② **除 `DecelerationAt` 自身与构造缓存外**，`_params.rollingDeceleration` 的出现次数 **== 0**（用正则计数）。
- **期望值来源**：**乙-结构**（"单点实现"的结构要求）。
- **判别力**：**漏改任一调用点**（仍读常量）⇒ FAIL —— 这正是 `T54` 抓不到的那一类。
- **盲带**：文本检查、**非语义证明**（别名/局部变量转发可绕过）。
- **注入负对照**：把「**TOI 后剩余时间推进**」那一处改回 `_params.rollingDeceleration`（§2.1 第二处）⇒ `T55` FAIL。

### T56a **两段形状（快-慢）**：前段减速显著大于后段
- **做法**：取**非退化**参数（`a_slide = 2.0`、`a_roll = 0.1`、`v_transition = 2.0`），记录速度曲线；
  取 `v ∈ (v_transition, v0]` 窗口的平均减速度 `d_hi` 与 `v ∈ (0, v_transition]` 的 `d_lo`，断言 `d_hi > 2·d_lo`。
- **期望值来源**：**甲**（模型定义式的直接推论：`v > v_t ⇒ a = a_slide = 20×a_roll`）。
- **判别力**：`a(v)` 写成**恒定** ⇒ `d_hi ≈ d_lo` ⇒ FAIL。
- **盲带**：只证"两段有区别"，**不证**"像真球"（那要 §8 扫描 + 用户判）；`v_transition` 的绝对值不在其中。
- **注入负对照**：`DecelerationAt` 里把 `clamp01(v/v_transition)` 换成常量 `1f`（⇒ 恒定 `a_slide`）⇒ `T56a` FAIL。

### T56b **单调性**：`a_slide` 越大 ⇒ 满力静止耗时越短（同 `a_roll`/`v_transition`）
- **做法**：`a_roll = 0.1`、`v_t = 2.0` 固定；`a_slide ∈ {1.0, 2.0, 4.0}` ⇒ 断言静止耗时**严格递减**。
- **期望值来源**：**甲**（"高速段扣得更多 ⇒ 更早停"的单调性；参数域内可证）。
- **判别力**：把 `a_slide`/`a_roll` 用反 ⇒ 单调性反 ⇒ FAIL；把两段权重写错 ⇒ FAIL。
- **盲带**：不覆盖"是否像真球"，也不覆盖用户要的"**滚得更久**"（那是**绝对值**问题，靠 §8 选值）。
- **注入负对照**：交换 `a_slide`/`a_roll` 的用法 ⇒ FAIL。

### T57 **不造能**（`a(v) ≥ 0` 恒成立）
- **做法**：① **参数域**：对 `a_slide ∈ [−1, 3]`、`a_roll ∈ [−1, 3]` 网格构造，断言 `DecelerationAt`（或等价的只读出口）**从不返回负值**；
  ② **实跑**：非退化档跑满力，断言速度**单调不增**且 `EnergyGainViolations == 0`。
- **期望值来源**：**甲**（`a ≥ 0` 是最小能量约束）。
- **判别力**：`a_roll` 设负 ⇒ 若内核不 clamp/拒绝 ⇒ 速度反增、`EnergyGainViolations > 0` ⇒ FAIL。
- **盲带**：只挡"造能"，不挡"耗散过大"（那是参数选择问题）。
- **注入负对照**：去掉 `Mathf.Max(0f, a)` 并把 `a_roll = −0.1` 写进测试夹具 ⇒ `T57` FAIL。

### T58 **确定性（非退化档）**
- **做法**：非退化档（`2.0 / 0.1 / 2.0`）4 球开球场景**双跑逐位一致**（位置 + 速度）。
- **期望值来源**：**乙-结构**（逐位一致是非解析判据）。
- **判别力**：引入 `HashSet`/`Dictionary` 迭代序、`Time`、`Random`，或让 `a(v)` 依赖历史 ⇒ FAIL。
- **盲带**：不覆盖"禁用清单不充分"（源码词表是结构性补充，非证明）。
- **注入负对照**：`DecelerationAt` 里加 `* (1f + Time.deltaTime*0f)`（或读一个 `static` 累计量）⇒ FAIL。

### T59 **门控**：两段都为 0 ⇒ 与历史"无滚阻"逐位一致；只有一段非零 ⇒ 生效
- **做法**：① `a_slide = a_roll = 0` ⇒ 与历史 `rollingDeceleration = 0`（门控为假、整段跳过）**逐位一致**；
  ② `a_slide = 0, a_roll = 0.1` ⇒ **生效**（静止耗时有限）—— 证明门控是 `||` 而非 `&&`。
- **期望值来源**：① **甲**（同一行为）；② **甲**（"非零即应生效"）。
- **判别力**：门控写成 `&&` ⇒ ② 永不静止 ⇒ FAIL。**这正是 `B4` 同族的"门控反了"缺陷**。
- **盲带**：不覆盖"两段都非零但被走成一段"（`T56a` 覆盖）。
- **注入负对照**：门控改 `&&` ⇒ `T59` ② FAIL。

### T60 **接线扩展**（`T41` **原地扩面**）
- **做法**：`T41` 的比对表**加上** `a_slide` / `a_roll` / `v_transition`（经内核只读出口，照 `RestSpeedThresholdValue` 先例）。
- **期望值来源**：**乙-结构**（资产 == 生效值）。
- **判别力**：新参数**只在资产里、没接进内核** ⇒ FAIL（`B4` 同款）。
- **盲带**：同 `T41`（只覆盖"已接线参数"）。
- **注入负对照**：把 `Initialize()` 里 `restSpeed = tuning.…` 那类赋值**连同新参数一起**注释掉 ⇒ FAIL。

### T61 **出厂口径冻结扩展**（`T44` **原地重钉**）
- **做法**：`T44` 的冻结表**重钉为 12 项**（`Q-14` (a) 已裁定：删 `rollingDeceleration`、加 3 新字段 ⇒ 10 − 1 + 3 = 12）。
- **期望值来源**：**乙-系数选定**（台账表；改值须显式重钉）。
- **判别力**：资产被悄悄改动 ⇒ FAIL。
- **盲带**：不覆盖"代码默认"侧面（与 `T43` 同族，见 §9 最危险条）。
- **注入负对照**：资产 `rollingDecelerationRoll` 改 `0.05` ⇒ `T61` FAIL。

### T62 **场景漂移扩展**（`T43` **原地扩面** —— `Q-15` (a) 已裁定 ⇒ **必做**）
- **做法**：把 `T43` 的断言面**扩到 3 个滚动字段**（`PhysicsTestDrive` 上新增的同名序列化字段，与回落集合一致），并在**场景重建后**核对。
- **期望值来源**：**乙-结构**（场景序列化值 == 代码默认值）。
- **判别力**：★ **只改场景里某个滚动字段（不动代码）⇒ 必须红** —— 这正是"守卫恰好在最可能要调的三个参数上瞎"的机械复现。
- **盲带**：① 只覆盖**已列入断言的字段**；`v_transition` 若未进场景则不适用（`Q-15` (a) 下应已进）。
  ⚠ ② ★ **注入值的盲带（主理人追加，`R-A2`/`R-E2` 同族）**：本条的注入**只在"注入值与出厂值必然不同"时有效** ——
  若**出厂值恰好等于写死的注入值**（或在容差内），注入就变成**空动作** ⇒ 会得到"守卫有效"的**假象**。
  ⇒ **注入值不得写死**（例如不许写死 `0.9`），必须**先读取真实出厂值，再取一个必然不同的数**（例如 `出厂值 + 0.37f`）。
- **注入负对照**：**读真实出厂值** `v = 资产.rollingDecelerationSlide`；把**场景**里的该字段改成 **`v + 0.37`**（**不改代码**）⇒ `T43`/`T62` **必须 FAIL**。
