# 工程标准（可执行版）

| 项 | 值 |
| --- | --- |
| 适用 | 本工程全部 C# 代码、资产管线脚本、验收器与测试 |
| 状态 | 生效中（用户长期指令：「**以后代码要按游戏公司标准实现**」） |
| 来历 | 由 `D4-AUDIT-01` 审计结论 + `D4-FIX-01` 整改落地；**每条规则都能被验证** |
| 配套 | `.editorconfig`（风格可执行化）、`Docs/adr/ADR-0001-坐标系与手性约定.md`（坐标约定） |

> **本文件是可判定的标准，不是价值观宣言。**
> 每条规则给出：**规则 → 如何验证 → 违反示例**。无法验证的条目不得进入本文件。

## 1. 程序集边界（分层）

| 程序集 | 平台 | 允许引用 | 内容 |
| --- | --- | --- | --- |
| `Billiards.Runtime` | **全平台** | `Unity.InputSystem` | 只有**玩家运行时会用到**的东西：`PoolConstants` / `PoolGeometry` / `TableConfig` |
| `Billiards.Diagnostics` | **Editor** | *（无）* | **只在导入/校验/测试时用**的东西：`TableReference`(DTO+比对) / `MeshAlignmentMetrics` / `MeshAlignmentTolerances` / `PhysicsBanAudit` |
| `Billiards.Editor` | Editor | Runtime, Diagnostics, `Unity.InputSystem` | 菜单 / 导入器 / 验收器 |
| `Billiards.Tests.EditMode` | Editor | Runtime, Diagnostics, TestRunner×2 | EditMode 测试 |

**R1-1** 依赖方向只能 `Editor/Diagnostics/Tests → Runtime` 与 `Editor/Tests → Diagnostics`。
**不得**出现 `Runtime → Editor/Diagnostics`，不得有任何循环。
- **验证**：`grep -rn "^using Billiards" Assets/_Project --include=*.cs` 逐条核对；或看 asmdef `references`。
- **违反示例**：`Runtime/Core/PoolGeometry.cs` 里 `using Billiards.Diagnostics;`

**R1-2** **Runtime 里不得有"零运行时消费者"的代码**。
- **验证**：对 Runtime 下每个 public 类型，`grep` 全仓引用；若消费者**全部**在 Editor/Tests，它就不该在 Runtime。
- **违反示例**：把 `MeshAlignmentMetrics` 放回 `Runtime/Core/`（整改前实测：Runtime 1118 行里 **667 行（60%）** 是这种代码，会被编进玩家构建）。

**R1-3** 命名空间与程序集**同名**（`Billiards.Diagnostics` ↔ `Billiards.Diagnostics`）。
- **例外（已记录）**：`Billiards.Editor` 程序集的命名空间是 `Billiards.EditorTools` ——
  因为命名空间若叫 `Billiards.Editor`，会与 `UnityEditor.Editor` 在 `using` 处产生歧义。
  **这是有意为之，不是疏漏**；改动前须评估全部 IDE 提示。

**R1-4** 程序集归属由**自动守卫**守住（见 R4-2），不靠评审时的记忆。

## 2. 命名与风格

**R2-1** 风格以 `.editorconfig` 为准（缩进 4/空格、LF、UTF-8、Allman 大括号、`System` using 在前）。
**R2-2** 命名：常量/公有成员/类型 → `PascalCase`；局部变量/参数 → `camelCase`；私有静态字段 → `_camelCase`；接口 → `IPascalCase`。
**R2-3** **Unity 序列化字段保留 `public` 字段**（不改属性）—— Unity 序列化不认自动属性。
**R2-4** 禁止无意义缩写（`Mgr`/`Cfg`/`Svc`）。领域缩写（`URP`/`GDD`/`TOI`/`FBX`）可用。
- **验证**：`.editorconfig` + `dotnet format --verify-no-changes`（有 dotnet 环境时）。

## 3. 测试要求

**R3-1** **每个实现任务必须自带"负路径"测试** —— 至少 1 条**能失败**的用例，证明主判据不是恒真。
- **验证**：新任务的测试文件里找"注入/翻转/变异"类用例（如 `Falsification_*`、`*_Negative*`、注入错位）。
- **违反示例**：只有 `Assert.Pass`（恒真）；或期望值由**被测常量自身**导出（近代数恒等式，改 ±1e-4 仍通过）。

**R3-2** **禁止恒真断言**。任何"永远通过"的检查都不得进入测试或验收器。
- **验证**：审读断言；或按审计方法"把输入改到明显错，看它是否失败"。
- **违反示例（已修）**：`PoolConstantsTests.TableTestAssembly_IsWired` 曾用 `Assert.Pass`。

**R3-3** **否证性结论必须双重验证**（"什么也没找到"本身就是否定性结论预期输出的样子）。
- **验证**：给出检索空间的定义 + 第二种检索方法。

**R3-4** 断言优先用**可判据数值**（`expected`/`actual`/容差），不用"看起来对"。
**R3-5** 测试**不得产生仓库改动**（不写 `Assets/`、不改已提交证据）；输出走仓库外或 `-outputDir`。

## 4. 守卫（Guard）的形态

**R4-1** **同一不变量的检查必须单点实现**（铁律 16）。
- **验证**：`grep` 该判据的核心表达式（如 `GetComponentsInChildren<Rigidbody>`），**应只在 1 个文件里出现**。
- **违反示例（已修）**：`SCN-04`（Day 1）与 `SCN-06`（Day 3）曾各写一份 Rigidbody 统计，且**已分叉**。
- **本工程已发生 3 次**（R3 两入口前置条件、R3 报告路径解析、SCN-04/06）⇒ 列为**架构评审固定检查项**：
  凡新增检查/守卫，先问「**同一个不变量还有没有别处在实现它？**」

**R4-2** **守卫优先进测试套件**（铁律 18）—— 因为本工程**没有 CI**，"验收器里的守卫"= 没人点菜单就不跑。
- **验证**：该守卫是否出现在 `Docs/Reports/*editmode-tests.xml` 的用例列表里（而不是只在验收器报告里）。
- **违反示例（已修）**：物理铁律原先只在 `SCN-04`/`SCN-06` 里，`-runTests` **完全不覆盖**。

**R4-3** 守卫必须带**非空转证据**：断言"扫到了 N 个对象"（N>0），否则"0 个违规"可能只是"0 个被扫"。
- **验证**：守卫输出里有 `scene=1 prefab=18` 这类计数，且有断言下限。
- **违反示例（已防）**：只断言 `RigidbodyCount == 0` 而不检查是否扫到文件。

**R4-4** 守卫触发**不得静默**：要么 FAIL，要么计成可断言的计数器。
**R4-5** **不得以删除检查作为让套件变绿的手段**（铁律 4）。

## 5. 架构铁律

**R5-1** **自研二维定长步进物理，禁止 Unity PhysX。** 球桌/球杆物理不得使用 `Rigidbody`/`Collider`；
运行时程序集不得引用 `UnityEngine.PhysicsModule`。
- **验证**（三条，缺一不可）：
  1. `PhysicsBanGuardTests.ScenesAndPrefabs_ContainNoRigidbodyOrCollider`（场景 + prefab，自动执行）；
  2. `PhysicsBanGuardTests.RuntimeAssembly_DoesNotReferencePhysXModule`（代码级，拦"来源"）；
  3. `SCN-04`/`SCN-06`（验收器侧，与 1 共用 `PhysicsBanAudit`）。
- **注意**：守卫的实现本身用到了 `Physics.IgnoreLayerCollision`（层隔离），**因此 Player 构建目前仍带 PhysX 模块**。
  去耦合方案（写 `DynamicsManager.asset` 而非调 API）见 D4-AUDIT-01 §8.3-⑤，**排在发布前**。

**R5-2** **坐标转换只允许一处**：`PoolGeometry`（见 ADR-0001）。场景/预制件不得对模型叠加手动旋转。
**R5-3** **确定性**：物理层不引 `Time.deltaTime` / `UnityEngine.Random` / 无序容器迭代序；开方/三角走单一口径。
**R5-4** 校验/生成**入口不得重建被校验对象**：产物缺失才生成，存在则只校验（否则只证明"生成器自洽"）。

## 6. 评审门（每个任务收尾必须全过）

| # | 门 | 判据 |
| --- | --- | --- |
| G1 | 离线编译预验证 | **0 warning / 0 error**（警告也算不合格） |
| G2 | EditMode 测试 | **全绿**，且总数不低于上一任务（不得以删除求绿） |
| G3 | 验收器 | 相关验收器 **FAIL 数 = 0**；改动如需证据，输出走 `-outputDir` 或仓库外 |
| G4 | 仓库整洁 | 除本次交付物外，`git status` 无意外改动 |
| G5 | 独立复核 | 涉及数据/几何/物理的任务，由**非实现者**独立重算关键数值 |

**G1 的已知局限（必须记住）**：离线编译把全部 `.cs` 编成**单一程序集**，
⇒ **无法校验 asmdef 的 JSON 合法性，也无法校验 asmdef 引用边界**。
这两类错误只能由 G2（Unity 编译）捕获。**故 G2 不可跳过。**

## 7. 已登记的错误模式（写作/检查时的自查表）

| # | 错误模式 | 实例 | 防范 |
| --- | --- | --- | --- |
| 1 | **用片面检索支撑全称否定命题** | 只 grep `Tests/` 就断言"全工程无守卫" | 全称否定必须**定义检索空间并证明其完备** |
| 2 | 检查**测了"方便测的量"**而非"需要成立的量" | AXL-04/05 测"最近顶点"而非"最近面点"；校验器先重建再校验 | 换度量 / 分离生成与校验 |
| 3 | **计数 ≠ 语义** | 用 grep 计数判"墓碑未清除" | 读改动点前后文 |
| 4 | **同一不变量两处实现 ⇒ 分叉** | SCN-04/06；R3 两入口 | 单点实现（R4-1） |
| 5 | **"我改了" ≠ "旧的没了"** | 替换只换上半段，留下重复 `<summary>` | 验证旧形式完全消失 |
| 6 | **元数据声称 ≠ 实测** | FBX 声明 Y-up 实为 Z-up；球杆"杆身 +Z"实为 Y | 实测优先，写进 ADR |
| 7 | **不可达的验收条款制造假通过** | "盲区 ≤0.1 mm"（该网格不可达）；"任意端点抓 1 mm"（不成立） | 条款须用实测证明可达成 |
| 8 | **恒真断言** | `Assert.Pass`；期望值由被测常量自身导出 | R3-1 / R3-2 |
