## 1. 诊断事实（本轮实测，可复现）

> 复现命令（Python 读 wav 头 + 采样，权重 = 全采样）：
> `python - <<'EOF' … wave.open / struct.unpack('<…h') … EOF`（口径：峰值 = 两声道逐样本绝对最大值；RMS = 全 0.8 s 逐样本均方根；`Lgate` = **> −50 dBFS 的有源段** RMS；`L50` = 全曲最响 50 ms 窗 RMS）。

### 1.1 物理层（与主理人实测逐位一致，本人已复核）

| 事实 | 值 |
| --- | --- |
| 格式 | 10 个 wav **全部** 22050 Hz / 2ch / 16-bit PCM / 17640 帧 = **0.800 s**（逐一致） |
| 立体声内容 | **两声道逐样本完全相同（dual-mono）** ⇒ 声像无信息；等增益缩放**不改变声像** |
| 峰值范围 | −37.2 … −24.6 dBFS（跨度 12.6 dB） |
| 全曲 RMS | −70.0 … −46.5 dBFS |
| **有源段长度** | **0.002 … 0.192 s**（strike 8 ms / hit 7 ms / rail 14 ms / pocket 49 ms / win 192 ms） |
| 有源段 RMS（Lgate） | −44.7 … −35.2 dBFS（跨度 **9.5 dB**，比峰值跨度**更集中**） |
| 有源段 crest（峰值−Lgate） | **6.1 … 10.8 dB**（比全曲 crest 14.8–34.0 dB **小得多**） |

### 1.2 两条**决定方案**的推论

1. **全曲 RMS 是无效口径。** 文件仅 **0.25%–24%** 有源，其余是极低电平尾；用全曲 RMS 当目标会要求 9–30 dB 压缩，
   把瞬态压成"糊"——**故本规格以「峰值天花板」定安全、以「有源段 RMS（Lgate）」定相对平衡**（§2.1）。
2. **"0.8 s 统一时长会叠厚"是旧 spec 的伪风险（R-2 可降级）。** 实测**有源段仅 5–65 ms（撞击类）**，0.8 s 的
   其余部分近静音 ⇒ **实际声学尾音极短，并发叠加有限**。（旧 `35-A_Day11_音频接入_spec.md` §7 R-2 据此**更正**。）

### 1.3 ⚠ 一个必须点名的**导入侧静默陷阱（本单最重要的发现）**

11 个 `.meta` **全部**含 `normalize: 1`。Unity 手册对 `Normalize` 的定义是：
> *"audio will be normalized during the **Force To Mono** mixing down process"* / *"After the down-mixing the signal is peak-normalized"*。
> （即 **Normalize 只在 `Force To Mono` 开启时生效**。）

本工程 11 个 `.meta` 的 `forceToMono` **均为 0** ⇒ `normalize: 1` **当前是惰性 no-op（无效果）**。
**结论**：运行时 AudioClip 的电平 = **磁盘上的电平**（−24.6 … −37.2 dBFS）⇒ **瓶颈确实在素材**，方案成立。
**但两条防线必须写死**：
- **D-1（必须核验）**：在编辑器里读回任一导入 AudioClip 的采样峰值 —— 应为 **−24.6 dBFS（pocket）/ −24.8（strike）**，
  **不是 0 dBFS**。若读到 0 ⇒ `normalize` 实际生效 ⇒ **本规格的"逐文件增益"会被导入侧抹平**，须先改导入设置。
- **D-2（必须防）**：**任何人**把任一 `.meta` 的 `forceToMono` 改成 1，`normalize: 1` 会**当场激活**，把该 clip 峰值
  拉到 0 dBFS、**抹平相对平衡**（§2.3 全废）。⇒ 建议**防御性地把 10 个 SFX 的 `normalize` 显式置 0**（改动量 1 字符/文件，
  与"归一化 wav"同属音频资产处理，是否纳入请见 §9 待裁定-4）。

### 1.4 播放侧参数（`T90` 钉住的纯逻辑，现状；本单**不改**）

| 项 | 值 | 影响 |
| --- | --- | --- |
| `VolumeForSpeed(rel, full=4.5)` | `Lerp(0.25, 1, clamp01(rel/4.5))` | 播放幅度 0.25–1.0（**连续**，无余量） |
| `PitchForSerial(serial)` | `1 + 0.06·((serial%3)−1)` = 0.94/1.00/1.06 轮转 | **确定性**抖动（无随机数） |
| `MaxSameKindPerFrame` | 3 | 同帧同类上界 |
| `MinRepeatIntervalSeconds` | 0.03 | 同类跨帧最小间隔 |
| `masterVolume` / `BgmVolumeRatio` | 0.8 / 0.45 | 最终输出 = `峰值 + 20log10(播放幅度 × 0.8)` |
| BGM 实测 | peak −14.6 / best-1s-RMS −30.1 dBFS ⇒ 播放侧输出 ≈ **−39.0 dBFS** | 见 §7.2 |

### 2.4 爆音处置口径（回答"unity 硬限幅 vs 软拐点"）

- **A（默认，推荐）：纯增益，零限幅。** 目标峰值已 ≤ −5 dBFS，缩放后峰值**按定义**即落在目标，**不可能过载** ⇒
  既不需要硬限幅、也不需要软拐点。**失真为零、确定性为零风险。**
- **B（仅"爽感集"或未来提响时）：软拐点优先，硬削波禁用。**
  - **软拐点（soft-knee）**：阈值 = 目标峰值，拐点宽度 3 dB，最大衰减 ≤ 2 dB（`tanh` 或三次软拐点），
    保留瞬态形状；**禁用 brickwall 硬削波** —— 它在"撞击瞬态"上产生可听偶次谐波（"撕裂/糊"），正是"重击糊"的来源。
  - **代价（必须登记）**：软拐点**降低 crest ⇒ 抬高 Lgate**，会让 §2.3 的平衡**整体位移**，须**重跑平衡表**；
    且软拐点属"后处理"，**在用户排除范围内** ⇒ 默认不做。
- **C（并发过载，非素材问题）**：真正的削波风险来自**同帧多声部功率叠加**（见 §5.4），由**限流 + 退让**处置，不靠素材限幅。

### 3.2 「总声压不许超过」规则（层内 + 帧内）

- **R-L（层内）**：同一事件各层**功率和 ≤ 类目标峰值**。两层 0/−6 dB ⇒ 功率和 = +0.97 dB ⇒
  **L1 基础电平要比类目标再降 1.0 dB**（实现口径：`PlayLayer(clip, pitch, vol_i)`，Σvol_i² ≤ 1）。
  **禁止**三层以上；**禁止**层内任一层电平 > 0 dB。
- **R-F（帧内，见 §5.4）**：同帧所有在发声部，功率和（`10·log10 Σ10^(P/10)`）**≤ −1 dBFS**。

## 4. 交付-3：力度分级（**Tier-2**；音量连续，仅"层数"分档）

`rel` = 接触事件相对速度（m/s），满档 `full = 4.5`（= 出厂初速上界）。
**音量走既有连续 `VolumeForSpeed`（拒绝量化 —— 避免阶跃"拉链噪声"）；分档只决定层数与音色意图。**

| 档 | `rel` 区间 | `VolumeForSpeed` 输出 | 层数 | 音高 | 音色意图 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| T0 轻碰 | `[0, 1.0)` | 0.25 – 0.417 | **1** | 轮转 | 干、柔、无尾 | 只 L1；"不被淹没" |
| T1 中 | `[1.0, 2.5)` | 0.417 – 0.694 | **1** | 轮转 | 单层 | 主体区间 |
| T2 强 | `[2.5, 3.5)` | 0.694 – 0.861 | **2** | 轮转 | 加 L2（脆点/闷体） | 分档起步 |
| T3 满 | `[3.5, 4.5]` | 0.861 – 1.000 | **2** | 轮转 | 全频 | 开球/满力 |

> `rel > 4.5` 一律按 T3（`clamp01` 既有行为）。

**确定性铁律（必须）**：
- **禁止 `UnityEngine.Random`**（本工程确定性纪律：热路径不含 `Random`/`Dictionary`/`HashSet`）；
- 音高**只**由 `PitchForSerial(_playSerial++)` 三值轮转给出（现状，`T90 (b)` 已钉）；
- 分档**只**由 `rel` 的闭式阈值决定；**层数**只由档位 + 帧内并发（§5.3）决定 —— **无任何随机/时间抖动源**。

## 5. 交付-4：限流与事件优先级（**Tier-2**，第 3 条为新增）

### 5.1 现状（`T90 (c)` 已守，**不变**）
- 同帧同类 ≤ 3（`MaxSameKindPerFrame`）；同类跨帧最小间隔 0.03 s（`MinRepeatIntervalSeconds`）；异类互不影响。

### 5.2 「每类第一声一定听得见」—— 可判定描述
- **帧内**：`TryAccept` 对同类计数，第 1/2/3 声必接受（拒绝条件为 `≥3`）⇒ **同帧每类首声必响** ✓。
- **跨帧**：新帧首声还须距该类上次 ≥ 0.03 s。若上一帧同类在 `t`、本帧首声在 `t+Δt < 0.03` ⇒ 拒。
  故精确表述为：**"距上次该类 ≥ 0.03 s 的第一声必响"**。开球时**第一声球-球**（此前无球-球）必响 ✓；
  紧接 0.03 s 内的密集同类声被压 —— 正是"不糊"所需。

### 5.3 优先级与抢占（可判定）
**优先级序（高→低）**：`pocket > strike > hit > rail`（奖励 > 玩家动作 > 纹理 > 低频）。
- **P1 同类 cap 不变**（§5.1）。
- **P2 层退让（新增）**：同一帧内，当 `hit` 或 `rail` 已接受 ≥ 2 声 ⇒ 该帧后续同类的声部**只发 L1、丢 L2**。
- **P3 帧上限（新增）**：以 `§5.4` 的功率和规则为上界；超限时**按优先级从低到高丢弃**，且**先丢 L2 再丢 L1**。
- **P4 pocket 豁免**：pocket 永不被抢占（其 kind 独占 slot；任何未来"复音上限"实现中 `pocket` 排最前）。
- **P5 strike 每帧至多一次**（现有计数增量语义，不变）。

### 5.4 开球"不糊"的合成处方（为什么够）
1. cap 3/帧/类 + 0.03 s 间隔（不变）；
2. **0.8 s 尾音极短**（有源段 5–65 ms，§1.2-2）⇒ 声学叠加**远小于**"0.8 s 全尾"的直觉；
3. 层退让（P2）把高并发帧的声部数压回单层；
4. **功率和上界核算**：最坏同帧 = `1×strike(−7) + 3×hit(−7.5) + 3×rail(−9)`，`master 0.8`：
   `10^((−7−1.94)/10)=0.1277` + `3×10^((−7.5−1.94)/10)=0.3415` + `3×10^((−9−1.94)/10)=0.2417` = **0.711 ⇒ −1.48 dBFS ✓（≤ −1）**。
   ⚠ 若启用 L2（功率再 +≈1 dB）⇒ ≈ −0.5 dBFS ⇒ **故 P2 在高并发帧必须退让**。
   ⚠ "爽感集"（+2 dB）在此最坏帧为 **+0.52 dBFS ⇒ 削波** ⇒ 这是**默认不采用爽感集**的直接理由。

### 5.5 实现侧必须核对的架构风险（交程基岩）
`SourcePoolSize = 6` **不构成真复音上限** —— `AudioSource.PlayOneShot` 允许在**同一 source 上多声部叠加**，
6 个 source 只是轮转播放，**不阻止**同帧 >6 声部同时在发声。⇒ 若 §5.4 的功率和要真正守住，
须由**限流计数**（已有）而非 source 池来保证；是否加"真复音上限"由程基岩定（**盲带，本单不预设**）。
