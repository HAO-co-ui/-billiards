## 1. 必须先有的出口（名字冻结）

> 三个出口都**只读**、只供判据/诊断用，不得被产品逻辑写；放在对应视图类上（与既有 `ResetRackForJudge` / `PracticeBallRowVisible` / `VisibleGroupChips` 同一范式）。

### E1　`PracticeHudView.VisibleStatusText`（`string`，**可为 `null`**）—— 为缺陷② 必须新增

- **语义**：返回**此刻真正显示在屏幕上**的那一段"状态文本"。
- **可见性口径**（三条同时满足才算"显示"）：① 控件自身 `isActiveAndEnabled`；② **所有祖先** `activeInHierarchy`；③ 所在画布/画布组未被关。
- **返回值口径（必须能区分"不可见"与"文本为空"）**：
  - 存在**可见**的状态文本控件 ⇒ 返回它的 `text`（**可能是空串 `""`**）；
  - **没有任何可见**的状态文本控件 ⇒ 返回 **`null`**。
- **覆盖范围**：至少覆盖 `_stateCaption`（状态条说明行）与 `_matchStatus`（对战状态行）；**按模式取那个可见的**（练习取状态条说明行、对战取对战状态行）；两者都不可见 ⇒ `null`。
- **为什么必须是"可见性"出口**：若只加一个 `StatusCaptionText`（直接回控件 `text`），它在缺陷② 下**照样非空**（文案在、控件被隐藏）⇒ 判据会假绿。**这条出口的全部价值就在"不可见返回 `null`"**。

### E2　`PracticeResultView.ShowCount`（`int`，只读、单调不减）—— 为缺陷③ 必须新增

- **语义**：结算卡**被打开过几次**。`Present(...)` 每成功执行一次 `+1`（练习 `Show()` 与对战 `ShowMatchResult()` **都计**）。
- **为什么不只看 `IsOpen`**：`IsOpen` 只能断"**此刻**开着没"；缺陷③ 的现场是"**开过又被关掉**"（`OnPlayAgain` / 再按 `R` 都会 `Hide()`）⇒ 现场自愈，只剩"球堆莫名回到开局"。**只有"次数"留得下足迹**。
- **边界**：`Hide()` **不**减；与 `IsOpen` 同生命周期（进程内静态）。

### E3　`PracticeHudView.OpponentNameText`（`string`，**可为 `null`**）—— 为缺陷① 必须新增

- **语义**：对战 HUD 右栏**对手名当前显示值**；对手块不可见（练习形态）⇒ `null`。
- **为什么必须新增**：缺陷① 的 bug 本体是常量 `OpponentDisplayName`（在途已删）。`T160(a1)` 断的是**同一个纯函数**⇒ 与实现同源，**抓不到"没接线"**；必须断"控件里**实际是什么字**"。
- **可见性口径**：同 E1。

### S1　`PracticeResultView.TryRequestReRack()`（`bool`）—— **接缝，不是出口**，为缺陷③ 的**行为级**验证必须新增

- **语义**：**"玩家按了重摆键"的唯一入口**。`Update()` 里 `Input.GetKeyDown(rackKey)` **只允许**调它；内部先过模式门（`drive.AiOpponentEnabled == false` 才放行）→ 放行则 `_tracker.RequestReRack()` 并返回 `true`。
- **为什么必须抽**：在途实现是 `if (!drive.AiOpponentEnabled && Input.GetKeyDown(rackKey))`——**门写在 `Update` 里，判据进不去**，只能退化成源码子串守卫；而源码守卫**守不住跨文件后果**（`Show()` 走练习形态、`ReloadRack()` 不清 `MatchOver`、球堆被重置）。`T160` 注释自己写了"C 的行为级验证在 EditMode 做不到"——**抽了这个接缝就能做到**。
- 抽出来后 `Update` 只剩一行 `TryRequestReRack();`（行为完全不变），源码守卫 `(c1)` 需同步改为断"`Update` 里调 `TryRequestReRack()`"（更稳：门只有一处，数得清）。

### E4　`PracticeResultView.TickSessionForJudge()` —— 为缺陷③ 的 `ShowCount` / `IsOpen` 断言必须新增（**第 4 个出口，理由见下**）

- **语义**：把 `Update()` 里"会话观察 → 结局判定 → 展示"这一段（`BeginRack` / `CountBalls` / `Observe` / `if (Outcome != None) Show()`）抽成**一个方法**；`Update()` 每帧调它一次，判据也可以调它一次。
- **为什么非它不可**：`Show()` **只**在 `Update()` 里被调用，而 EditMode **不跑 `Update`**。没有它，`ShowCount` / `IsOpen` 在 EditMode 里**永远不变** ⇒ `C2/C3` 会变成恒真（比不写更糟：给人"已覆盖"的错觉）。
  有了它：对战里 `TryRequestReRack()`（返回 false）→ `TickSessionForJudge()` ⇒ 应当**什么都没发生**；若门被删，`RequestReRack` 置了 flag ⇒ 这一次 tick 就会 `Show()` ⇒ `ShowCount +1`、`IsOpen == true` ⇒ **C2/C3 红**。这才是"有牙"。
- **行为不变的约束**：抽取**只许搬代码，不许改顺序**；`Update()` 里该段的位置（在 `IsOpen` 早退、`MatchOver` 早退**之后**）必须保持原样。
- ⚠ 命名：本文件原先只冻结了 3 个出口；E4 是写测试骨架时发现的**必要性缺项**（`Show()` 只在 `Update` 里调），已向主理人备案。名字同样冻结。

**主理人已追认（含三条约束，删这个出口前先读这三条）**：
1. **只搬不改**：顺序必须保持 `BeginRack → CountBalls → Observe → if (Outcome != None) Show()`，
   仍位于 `IsOpen` 早退与 `MatchOver` 早退**之后**；`Update` **每帧调它一次**；行为逐位不变。
2. **本节"为什么非它不可"必须保留** —— 将来有人想删 E4 时，看到的就是这段理由。
3. **`B5` 出口自检（§3）继续是人工注入项**，不许降级成"注释里提一句"。

## 2. `T161(a)` —— 对手名必须等于**所选档位**，且随换档更新（缺陷①）

### 前置状态
1. `PracticeHudView` 探针：`new GameObject` → `AddComponent<PracticeHudView>()` → `EnsureBuilt()`（照 `ClubUiTests.cs:986-990`；**EditMode 下 `AddComponent` 不触发 `Awake`，必须显式 `EnsureBuilt`**）。
2. `PhysicsTestDrive` 夹具：`tableConfig` 载 `DriveTableConfigPath` → `Initialize()` → `hud.drive = drive`（照 `ClubUiTests.cs:1619-1632`）。
3. 难度只经 `drive.StartMatch(tier)` 写入（`MatchTier` 唯一写入口，`PhysicsTestDrive.cs:1193`）。

### 触发动作
对 `tier ∈ {Casual, Club, Expert}`：`drive.StartMatch(tier)` → `hud.ApplyMatchHud(true, GroupState.OpenTable, GroupState.OpenTable, false, empty, empty)`（等价于让 `hud.Refresh()` 跑一帧）。

### 必须断言的量
- **A1**　`hud.OpponentNameText == PracticeHudState.OpponentName(tier)`，**三档逐一**。
- **A2**　三档的 `OpponentNameText` **两两不等**（把"恒等于某一档"单独钉死；只断 A1 可能"比较对象写歪也绿"）。
- **A2b（滞留检查，专抓"指纹没含档位"）**　**同一 `hud` 实例不重建**：`StartMatch(Club)` → 读值 → `StartMatch(Expert)` → `ApplyMatchHud(...)` → 读值 ⇒ 两次值**必须不同**（在途实现把 tier 进了 `MatchHudSignature`，这条就是守它；少进指纹 ⇒ 名字停在上一个档位）。
- **A3**　练习形态 `ApplyMatchHud(false, ...)` ⇒ `OpponentNameText == null`（对手块不可见时**不该有值**；顺带守"练习不该显示对手"）。
- **A4**　源码守卫（与 `T160(a2)` 分工，**不重复**）：`_oppName.text =` 的**非空**赋值处，右侧必须出现 `drive.MatchTier`（不是常量、不是 `MatchSetup.Selected`——对局内真源是驱动器的 `MatchTier`）。

### 负对照
- **N1**　把 `ApplyMatchHud` 里的按档位赋值改回 `"Expert AI"` ⇒ **A1 红**（Club 档实测 `Expert AI`）。
- **N2**　三档都取 `OpponentName(AiDifficulty.Expert)` ⇒ **A2 红**、A1 在 Casual/Club 档红。
- **N3**　`ApplyMatchHud` 不更新 `_oppName`（保留构建时初值）⇒ **A1 红**。
- **N4**　把 `drive.MatchTier` 从 `MatchHudSignature` 里去掉 ⇒ **A2b 红**（名字滞留上一档）。

## 3. `T161(b)` —— 被拒提示必须**真的显示出来**（缺陷②）

### 前置状态
1. HUD 探针 + `hud.drive = drive`（同 §2 前置 1-2）。
2. `drive.StartMatch(AiDifficulty.Club)` ⇒ 对战形态（`AiOpponentEnabled == true`）。
3. **`drive.SetTurn(ShotTurn.Ai)`** —— 对战状态行只在"状态 ≠ `Aim`"时显示（`showStatus = aiMatch && status != StateAim`），
   回合在玩家侧时标题是 `Aim` ⇒ 状态行整块隐藏 ⇒ 读到的会是**假红**。
4. **`PracticeResultView.Hide()`**（保证 `IsOpen == false`）。
   ⚠ 不能省：`OpponentNoticeAllowed(IsOpen)` 在结算卡打开时会**丢弃**提示（`PracticeHudView.cs:950-954`）⇒ 不关卡会得到假红，或反过来掩盖真问题。
5. `MatchTurnNotice.Reset()`。

### 触发动作
1. `MatchTurnNotice.RequestBlock(MatchTurnNotice.ReasonOpponentTurn)` → `hud.Refresh()`（消费 pending、开窗口、写状态标题）。
2. **再显式按对战形态写一次 HUD**：`hud.ApplyMatchHud(true, OpenTable, OpenTable, aiTurn: true, 空, 空)`。
   ⚠ **这一步是"夹具必须真的进入被测形态"的硬要求**：`Refresh()` 内部 `RefreshGroupChips()` 用
   **`HomeView.IsAiMatchSession`** 定形态（`PracticeHudView.cs:1518`），而 EditMode 夹具不过首页 ⇒ 恒 `false`
   ⇒ `Refresh()` 会把 HUD 刷回**练习**形态。
   **实测教训（本判据曾因此假绿）**：只调 `Refresh()` 时，读到的是**练习那句**
   `Clear the colors, then the 8 ball` → 被拒后变成 `OpponentBlockedDetail`（来自 `_stateCaption`），
   而**对战分支从未被执行** ⇒ 把对战分支改成"永不显示"（`showBlocked=false`）判据**照样绿**。
   补上本步后同一注入**红**（`(b1)` 实际 `"Opponent"`）。
3. 读 `hud.VisibleStatusText`。

### 必须断言的量
- **B1**　`hud.VisibleStatusText == PracticeHudState.OpponentBlockedDetail`（逐字）。
- **B2**　该值 **不得等于** `PracticeHudState.AiTurnDetail`（常驻说明 = "没有新提示" = 静默）。与 `T144③` 末条同义，但断在**可见层**——缺陷② 正是在这一层漏的。
- **B3**　`hud.VisibleStatusText != null`（**控件真的可见**；`null` = 静默）。
- **B4**　练习形态同样要能看到：`ApplyMatchHud(false, ...)` + `RequestBlock` → `Refresh()` ⇒ 仍满足 B1/B3（**防"修对战把练习弄坏"**）。
- **B5（出口自检，必须做）**　把 E1 临时改成"直接返回 `_stateCaption.text`、不看可见性" ⇒ **B3 必须红**。没有这条，E1 自己可能被写成恒真，"看得见"永远测不出来。

### 关于"1.6 秒后自动消失"（**本判据不断**）
窗口用 `Time.unscaledTime` 判定（`PracticeHudView.cs:953`），EditMode 里 `Time.unscaledTime` **不随等待前进**（`Thread.Sleep` 也不动它）。
⇒ **不为一句话引入可注入时钟**（多一个活门 = 多一处可被产品逻辑误用）。
⇒ "约 1.6 秒后消失"交给**实机 C4** 判；本判据只断"窗口内可见 + 不等于常驻说明"。

### 负对照
- **N1**　把 `_stateCaption` / `_matchStatus` 的可见性**恢复成现状**（对战形态两者都隐藏）⇒ **B1 / B3 红**（这就是抓本次回归的那一枪）。
- **N2**　从 `RefreshStatusBar(..., opponentBlocked)` 调用里去掉该实参 ⇒ **B1 红**。
- **N3**　出口自检：E1 不看可见性 ⇒ **B3 红**（见 B5）。

## 4. `T161(c)` —— 对战里按 `R` 不得生效、且状态逐位不变（缺陷③）

### 前置状态
1. `drive` 夹具 + `drive.StartMatch(AiDifficulty.Club)` ⇒ `AiOpponentEnabled == true`、`MatchOver == false`。
2. `PracticeResultView` 探针：`AddComponent<PracticeResultView>()` → `drive` / `hud` 赋值 → `EnsureBuilt()` → `Hide()`。
3. 触发**之前**取全基线：
   - `int showCount0 = PracticeResultView.ShowCount;`
   - `bool matchOver0 = drive.MatchOver;`
   - `ShotTurn turn0 = drive.CurrentTurn;`
   - `GroupState group0 = drive.PlayerGroup;`
   - 球心快照 `Vector2[] rack0`：`drive.Simulator` 逐颗 `position`（**含白球**，按球号取）。

### 触发动作
1. `practiceResultView.TickSessionForJudge();` —— **先起局**（跑一次会话 tick）。
   ⚠ **这一步不能省**：`PracticeSessionTracker.BeginRack()` 会把 `_reRackRequested` **清零**，而首帧 tick 才 `BeginRack`
   ⇒ 若先按 `R` 再第一次 tick，"重摆请求"会被**静默吞掉** ⇒ 即使删掉模式门也不会 `Show()` ⇒
   `(c2)(c3)` 变成**哑巴**（工程侧 `INJ-161c` 实测：删门后只有 `(c1)` 红）。
2. `bool accepted = practiceResultView.TryRequestReRack();`（接缝：门 + 置请求）
3. `practiceResultView.TickSessionForJudge();`（再跑一次 tick ⇒ 本判据的 `Show()` 只可能在这里发生）

### 必须断言的量
- **C1**　`accepted == false`（模式门生效）。
- **C2**　tick 之后 `PracticeResultView.IsOpen == false`（当场没开卡）。
- **C3**　tick 之后 `PracticeResultView.ShowCount == showCount0`（**一次都没打开过**，含"开了又关"；只断 C2 断不到后者）。
  　⇒ C2/C3 有牙的前提是 **N1**（去掉门 ⇒ 必须红），已写入负对照。
- **C4**　`drive.MatchOver == matchOver0`（**不得结算**）。
- **C5**　全部球心**逐位不变**（`rack0` 与当前逐颗精确相等，白球一并断）。
- **C6**　`drive.PlayerGroup == group0` 且 `drive.CurrentTurn == turn0`（组别/回合**不得被重置**）。
- **C7（反向不变，防"一刀切禁掉 R"）**　`drive.EndAiMatchSession()` ⇒ `AiOpponentEnabled == false`；再 `TryRequestReRack()` ⇒ 返回 **`true`**，且 `TickSessionForJudge()` 之后 `ShowCount == showCount0 + 1`（练习里的 `R` **必须仍可用**并**仍然会弹练习卡**，P23/P27 语义不许被带坏）。

## 6. 注入（负对照）纪律

每条负对照都要**真的跑一次并留档**（红 → 还原 → 绿），否则等于没写：

1. **备份必须在仓外**（`%TEMP%\...\bak`）——仓内 `Temp/` 会被整体清空（规格 §7 已登记事故）。
2. `backup` 写 `baseline.sha1`；`apply-*` 前断言 `当前 == baseline`；`restore` 后**回读并断言 `== baseline`**。
3. 台账登记：注入名 / 预期红的子号（如 `T161(b) B1`）/ 实跑结果 / 还原后 sha1。
4. 建议注入最小集（**6 次**）：`INJ-161a`（常量回退）、`INJ-161a'`（tier 移出指纹）、`INJ-161b`（可见性回退）、`INJ-161b'`（E1 不看可见性）、`INJ-161c`（去门）、`INJ-161c'`（`ReloadRack` 清 `MatchOver`）。

## 9. 复盘登记：这套判据自己差点变成假绿的**三个地方**

写判据最大的风险不是"没写"，而是"写了但它是哑巴"。本批三个都真实发生过，留在这里防复发：

| # | 哑巴形态 | 怎么发现的 | 现在的解药 |
|---|---|---|---|
| 1 | `Show()` **只在 `Update()` 里被调用**，而 EditMode 不跑 `Update` ⇒ `ShowCount` / `IsOpen` 永不变化 ⇒ `(c2)(c3)(c7)` 恒真 | 写骨架时静态读 `PracticeResultView.Update` | **E4 `TickSessionForJudge()`**（并把"为什么非它不可"写进代码注释，防止将来被删） |
| 2 | 夹具**没真的进入被测形态**：`Refresh()` 按 `HomeView.IsAiMatchSession`（EditMode 恒 `false`）刷成**练习**形态 ⇒ 对战分支从未执行，`(b)` 读到的其实是练习那句 | 工程侧把对战分支改成"永不显示"做负对照，**判据照样绿**；探针显示 `before = "Clear the colors…"`（练习文案） | `drive.SetTurn(Ai)` + `Refresh()` 之后**再显式 `ApplyMatchHud(…, aiTurn:true, …)`**（§3 触发第 2 步） |
| 3 | **`BeginRack()` 会清 `_reRackRequested`** ⇒ 先按 `R` 再首帧 tick，请求被静默吞掉 ⇒ 删掉模式门也不会 `Show()` ⇒ `(c2)(c3)` 只在文本上"看起来有牙" | 工程侧 `INJ-161c`（删门）实测：**只有 `(c1)` 红** | 触发顺序固定为 **先 tick 起局 → 取基线 → 按 `R` → 再 tick**（§4 触发第 1-3 步） |

**给将来加 UI 判据的人的三句话**：
1. 断"**玩家看到什么**"，不要断"纯函数算出什么"（`T144③` 的教训）；
2. 断之前先证明**夹具真的把被测形态跑起来了**（第 2 条：形态刷错，判据就在测别的东西）；
3. 每条断言都要能回答"**把实现改坏，它会不会红**"——答不出来就是哑巴（第 1、3 条）。

**再补一句关于第 3 条（这一类缺陷的共同特征，最值得记）**：
`BeginRack` 这种"**在起点就把请求清掉**"的写法，**断言读到的一律是"终态"**（`ShowCount` 没变、`IsOpen` 是 false、球没动），
所以**读断言永远看不出它坏**——只有**拿负对照打**（把模式门删掉、看判据会不会红）才暴露。
⇒ 结论：**"负对照"不是流程装饰，它是判据的标定过程**。本批六次注入（`INJ-161a/a'/b/b'/c/c'`）的价值就在这里：
它们同时标定了"判据在正确实现下是绿的"和"在错误实现下是红的"——**只有前者就叫没标定**。

## 10. **下一批次（P38）待办**：两条"靠入口不存在来保证安全"的设计

> **本批（P37）不做**，但**不留白**。下面两条现在**不可达**，所以不进本批的必过项；
> 它们被单列一节的唯一理由：**"它现在不可达"是靠"入口恰好不存在"保证的，不是靠门保证的**——
> 一旦将来出现第二条能在对战里开卡的路径，**立刻变成 Critical**。这类设计必须补门，不能靠运气。

### 10.1 `PracticeResultView.OnPlayAgain()` 没有模式门
- **现状**：`OnPlayAgain()` 直接 `_tracker.NotePlayAgain(); StartNewRack();`，而 `StartNewRack()` → `drive.ReloadRack()`
  （`ReloadRack` 会清 `ruleState`/组别/回合/待放球/`AiPhase`，见 10.2）。**全程没有判断当前是不是对战。**
- **为什么本批安全**：对战里**根本不会出现结算卡**（`TryRequestReRack()` 返回 `false`、`Update` 的结算分支只在对战真有结局时走 `ShowMatchResult`），
  所以"点 `Play again` / 卡上再按 `R`"这条路在对战里**不可达**。它由 `T161(c1)(c3)` 守着。
- **一旦可达的后果**：**Critical** —— 一局对战被静默清零（球堆回开局、组别/回合归零、`MatchOver` 仍 `false`、不结算、AI 仍启用），
  症状与用户操作之间**没有可见因果**（用户只会说"它自己重置了"）。
- **最小改法（建议）**：`OnPlayAgain()` / `StartNewRack()` 入口加与 `TryRequestReRack()` **同一判据**的门
  （`drive != null && drive.AiOpponentEnabled` ⇒ 拒绝 + 给出可见反馈，**不许静默**）。
- **需要的判据**：行为级 —— 对战 + 人为把卡打开（走诊断接缝）后调 `OnPlayAgain()` ⇒
  球心逐位不变 / `MatchOver` 不变 / `PlayerGroup` 与 `CurrentTurn` 不变 / `ShowCount` 不增；
  **负对照**：把门删掉 ⇒ 必须红（这条判据才有牙）。

### 10.2 `ReloadRack()` 不清 `MatchOver` / 不清 `AiOpponentEnabled`
- **现状**：`PhysicsTestDrive.ReloadRack()`（`PhysicsTestDrive.cs:480-517`）清了 `ruleState`、`PendingCueBallPlacement`、
  `_cueBallLeftTableSinceLastLaunch`、`AiPhase`，**但不清 `MatchOver`、不清 `AiOpponentEnabled`**。
- **为什么本批安全**：同上——对战里进不到"重摆"这条路。
- **一旦可达的后果**：**Critical 且更难查** —— HUD 仍是**对战形态**（`AiOpponentEnabled` 还是 true）、球台却已回开局、
  又**不结算**（`MatchOver` 仍 `false`）⇒ "对局被悄悄换了底"。
  ⚠ 反过来，如果误在**练习**里清了 `AiOpponentEnabled`，会退化成本仓已修过的 P25/P27 那类缺陷
  （练习显示对手 / 发不出球）⇒ **改这条必须双向断**，不许只加一边。
- **最小改法（建议）**：把"重置"改成**显式声明模式**：`ReloadRack(RackResetMode mode)` 或
  `BeginPracticeRack()` / `BeginMatchRack()` 两个入口，让"清不清 `MatchOver`"由**调用方语义**决定，
  而不是由"谁来调"隐式决定。
- **需要的判据**：① 对战路径重摆 ⇒ `MatchOver` 按语义取定值、`AiOpponentEnabled` 保持 true、随后能正常出杆；
  ② 练习路径重摆 ⇒ `AiOpponentEnabled` 保持 false、HUD 无对手（**反向不变**，守 P25/P27）；
  ③ **负对照**：任一侧改错 ⇒ 必红。

### 10.3 两条的共同验收口径
P38 收口时，这两条按"**三道**"判：**行为断言 + 负对照（改坏必红）+ 实机一眼能看出**（对战里点 `Play again`／按 `R` 后
**球堆/回合/组别都没变**）。只绿一道 = **CONCERNS**，不许算完。
