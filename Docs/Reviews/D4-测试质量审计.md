## 四、项 3：`static` + `[OneTimeSetUp]` 的污染与顺序依赖

事实（`TableConfigTests.cs:39-66`）：`static TableConfig _config`、`static TableMetaDto _a/_b` + `[OneTimeSetUp]`；`Config` 属性内含 `Assert.IsNotNull(_config, ...)`。

| 问题 | 评估 |
| --- | --- |
| 跨测试污染 | **当前无**：`grep` 证实**无任何测试写入** `Config`/`_config`（`Config.x =` 0 命中）✓ |
| 顺序依赖（fixture 内） | **无**：`[OneTimeSetUp]` 在全部测试前跑一次 ⇒ 所有测试看到同一状态 ✓ |
| **`static` 的必要性** | **无必要**：NUnit 每个 fixture 只实例化一次，`_config` 用**实例字段**即可。`static` 让它成为**进程级缓存** |
| **风险（Day 4+ 埋雷）** | 若后续 fixture 重新生成 `TableConfig.asset`，本 fixture 的 `_config` 仍指向**被替换前的旧对象** ⇒ **静默使用陈旧数据**；且顺序依赖会随测试数增长而出现 |
| 空引用风险 | `SegmentCount => segments == null ? 0 : ...` 有守卫，但 `Segments_AreNonDegenerateAndInsideEnvelope`(:139) 等**直接迭代** `Config.segments` ⇒ 若字段为 null 会 NRE（`TableConfig.cs:59` 是 `public` 可空字段） |

**建议（低成本）**：`static` → 实例字段；或在 `[SetUp]` 里断言 `_config` 非空并校验其 `sourceSha256` 与磁盘一致。
