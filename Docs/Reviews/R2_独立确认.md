### 2.1 ⚠️ 我对"第 96 行无条件 `Import()`"的判定（你未断定、我判定）
**位置**：`TableIntegrityValidator.ValidateInteractive()`，标注 `[MenuItem("Billiards/Verify/Validate Table Data & Art (Day 2)")]`，其中 **:96 `TableDataImporter.Import();` 无任何守卫**。

**判定：不是"有意的独立导入入口"，而是"校验路径上的残留"** —— 理由：
1. 该入口**自名 "Validate"**（不是 Import）；而**另有独立导入菜单** `Billiards/Data/Import Table Reference Data`（在 `TableDataImporter`）⇒ 这里的 Import **冗余**；
2. 团队对 Day-3 的处置标准是"**只有非校验入口才可保留重建**"（`RenderOnlyFromCommandLine` 明确写了"不是校验入口"）。按同一标准，此菜单**名为 Validate 却重建对象** ⇒ **违反 R2 原则**；
3. ⇒ 在 Editor 里点该菜单，**仍会先重建 `TableConfig.asset` 再校验** ⇒ 同缺陷的**交互形态仍在**。

⇒ **CONCERN C2-1（中）**：R2 修好了**批处理/CI 路径**，**未修交互菜单路径**。

> **本条是对 `7f05e39` 这个冻结修订的判定，不是对未来修订的。**
> 已知 **R3** 将做**结构性修复**（把两处入口的前置条件抽成共享 helper，根因是"两个入口各写一份前置条件"），
