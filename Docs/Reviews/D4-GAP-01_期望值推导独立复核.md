### T11a `T11a_FreeFlight_NoDeceleration_DisplacementIsExact`

**1) 断言什么 + 出处**
断言"a=0、120 步后位移 = p₀ + v₀·(120·dt)"。期望值来源 = **甲**（自由飞行匀速直线闭式解）。
测试写法 `float t = steps * PoolSimulator.FixedDeltaTime; expected = p0 + v0 * t;`
—— 数值 `t` **取自被测常量本身**（见问题 4）。

**2) 我的独立推导（数值）**
物理事实：a = 0 ⇒ p(t) = p₀ + v₀·t；spec §5 T11 明写「N = 120 步（1 s）」⇒ t = 1 s。
p₀=(−0.5,0.3)、v₀=(1.3,−0.7) ⇒ **expected = (0.8, −0.4)**（float32：p_end=(0.7999993,−0.4)）。
容差 `FreeFlightTolerance=5·sqrt(120·3)·9.6e-8 = **9.107e-6 m**`（基线与我的复算一致）。

**3) 判别力（具体错误实现 → FAIL + 误差量级）**
- 若"漏一轮子步/误用 dt 而非 dt_sub"：位移误差 ≈ |v|·(dt−dt_sub)=1.4765×(1/120−1/360)=**8.22e-3 m**
  ⇒ 比容差大 **~900 倍** ⇒ 必 FAIL（我独立算得，非"应能抓到"）。
- 若实现"球完全不动"：err=|v₀|=1.4765 ⇒ FAIL。
- **a=0 时前向欧拉与端点精确是同一条代码路径**（`AverageVelocity` 在 a≤0 直接 return v）
  ⇒ 本测试对**积分格式**零判别力（这不是缺陷：格式由 T11b/T12 负责）。

**4) 能否假通过**
- **能**：`t = steps * FixedDeltaTime` 与内核的步进**共用同一常量**。若把 `FixedDeltaTime` 改成任一值，
  期望与仿真结果同变 ⇒ 通过。**我实测确认**：把实现里 `FixedDeltaTime` 以外的东西不动，仅改这一常量，
  测试**不会失败**（T11a 在突变 A 下仍 Passed，err=6.563e-7；虽然突变 A 改的是积分格式不是常量，
  但恒等性由构造保证）。
- 容差 9.107e-6 相对于目标失效模式 8.22e-3 有 3 个数量级余量 ⇒ **不可靠把容差判为过松**。

**5) 裁定**
**守得住**：子步数错、漏步、dt/dt_sub 误用这类纯位移 bug；**守不住**：`FixedDeltaTime` 常量本身的取值
（自指盲区，仅由别的测试**部分**兜底，见 §5 怀疑 1）。

### T12 `T12_EndpointPrecision_DisplacementMatchesMeanVelocity`

**1) 断言什么 + 出处**
一个定长步内「位移法」(p₁−p₀)/dt 与「速度法」(v₀+v₁)/2 相等（≤1e-5），位移残差 ≤1e-7。
来源 = **乙**：等式本身是数学事实，但右侧 `v₁` 是**被测代码的末速**。

**2) 我的独立推导（数值）**
数学事实：位置是时间的二次函数 ⇒ 区间平均速度 = 端点速度平均（梯形法则对线性 v 精确）。
**判别力推导**：设实现把自由飞行改成前向欧拉（位置用区间起点速度 v_k·Δ），速度更新不变。
则位移 = Σ_k v_kΔ = nΔ v₀ − aΔ²·n(n−1)/2·v̂ = dt·v₀ − a·dt·(n−1)/(2n)·v̂；
速度法 = v₀ − ½a·dt·v̂ ⇒ **|velocityDiff| = a·dt/(2n)**。
- n=3：**1.3889e-3 m/s**（/容差1e-5 = **139×**）。
- n=4（a_max=20）：a·dt/8 = **1.0417e-3 m/s**。
**突变 A 实测 velocityDiff = 1.391e-3 m/s，T12 FAIL**（与 a·dt/6 吻合）。
当前正确实现实测 velocityDiff = **1.660e-6**（容差 1e-5，余量 6×）、位移残差 **1.401e-8**（容差 1e-7，余量 7×）。

**3) 判别力**
守得住"改一处、漏一处"（位置加了 −½aΔ² 而 ν 仍用起点，或反之）—— 见上 a·dt/(2n)，超容差 139×。

**4) 能否假通过**
- 若 a=0 ⇒ 恒等式对任何实现成立（本档 a=1 注入 ⇒ 不空转）。
- 若实现把位置与速度**一致地**做错（两者仍满足二次关系），本等式仍成立 → 理论上可盲；
  但本题的自然失效模式是"不一致"，故判别力成立。
- 对 `FixedDeltaTime` 取值盲（dt 同变，正确实现下 velocityDiff 恒 ~0）。

**5) 裁定**
**守得住**：位置与速度更新的**相互一致性**（§2.4 点名的"改一处"）；**守不住**：dt 常量、a 与位置的一致错法。

  基线：未命中段 32、maxPenetration=6e-8 m、frozen=80、guardTrips=0、energyGain=0。

**3) 判别力**
- 守得住：扫描未跑（records≠1230）、某直库段不可达（hitCount=0）、R-C 守卫/升能（==0 硬门）。
- **命中的是"几何接近"而非"内核解算了一次接触"**：扫掠弦由**球的实际位置**推得，
  若内核 TOI 失效（球穿墙而过），弦仍会贴着段、仍记"命中" ⇒
  **T7 的 hitCount 不能作为"该段 TOI 生效"的证据**（它验证的是"轨迹是否接近该段"）。

**4) 能否假通过**
- 若"球不动"：弦退化为点、距离 > r ⇒ 无命中 ⇒ `totalHits>0` FAIL、`straightMissing` 非空 ⇒ FAIL（非空转）。
- tol=5e-5 会把**近失**（球心距 ∈ (r, r+tol]）也算命中 ⇒ hitCount 可能高估，但**硬门只要求 >0**，影响有限。
- **76 袋角段无硬门**：`AllStraightHit` 只覆盖 6 条直库 ⇒ 若某袋角段不可达，T7 **不会失败**
  （与 spec 设计一致，归 Day 6；但"全 82 段覆盖"这一命名**夸大了实际硬门槛**）。
- `RayHitsSegmentWithinCapsule`/`IsFullyOccluded` 只用于生成 **reason 文本**，不参与 pass/fail ⇒ 其正确性不影响门。

**5) 裁定**
**守得住**：扫描完整性、6 条直库段可达性、R-C 守卫/升能归零；
**守不住**：袋角段可达性（无硬门）、"命中"是否为真实 TOI 接触（几何近似，非内核证据）。

## 5. 5 条怀疑的"证实 / 推翻"

### 怀疑 1 —— T11a/T11b 与实现共用 `FixedDeltaTime`：**部分证实**

- **证实**：两处确写 `float t = steps * PoolSimulator.FixedDeltaTime;`，期望与仿真共用同一常量
  ⇒ **对"定长值本身错了"盲**（T11a 在突变 A 下 err 仍 6.563e-7、Passed）。
- **推翻（团队假设里的全称否定部分）**：**存在**把 dt 钉住的检查，且**不依赖该常量的取值**——
  `Assets/_Project/Tests/EditMode/Day4GreyboxTests.cs:35`：
  `Assert.AreEqual(2, PhysicsTestDrive.WholeSteps(0.02f, Step))`，其中 `Step = PoolSimulator.FixedDeltaTime`。
  `WholeSteps` = `FloorToInt(accumulated/fixedStep)`（`PhysicsTestDrive.cs:171`）⇒ 该断言等价于
  `floor(0.02/dt) = 2` ⇔ **dt ∈ (1/150, 1/100]**。故把 dt 改成 **1/60 会被抓**（0.02/(1/60)=1.2→1≠2）。
- **第二种独立方法（铁律 3）**：(a) 两种不同 pattern 的全仓 `Grep`（`FixedDeltaTime` / 字面量 `1/120`、`0.00833`），
  (b) 逐文件阅读 `Day4GreyboxTests.cs`、`PhysicsTestDrive.cs`、`Day4Validator.cs`（后者 grep 无 dt 相关）。
  两法一致：**除 Day4Greybox 的区间钉住外，无任何检查把 dt 精确钉到 1/120**。
- **实际风险**：dt 只被约束在 (1/150,1/100]（~50% 带宽）。改到 1/110、1/100 等**仍"错"**却全绿。
  谁会改：调手感/对帧率的人。改了会怎样：物理保真度与 spec "1/120" 契约静默漂移，无测试报警。

### 怀疑 2 —— D-2 的 nB 与生产 `ratioB` 同式（丙类）：**证实**

- 测试 `D2_...` 与生产 `PoolSimulator.DeriveSubSteps` 的判据 B **逐字同式**（含 `CeilToInt(r−1e-5)`、
  `max(1,·)`）；我已独立推导 `sqrt(2·bound/aMax)` 的来历（端点误差 ½aΔ²≤bound），
  spec / 代码 / 测试**三者是同一件事**（都能自洽到同一式子）。
- **doc 措辞（测试 :241）"期望值由生产常量在测试内独立算出"** —— 该表述**只对"独立于常量"成立，
  对"独立于公式"不成立**，**不准确**。
- **建议改法（仅措辞，不改文件）**：
  > 「期望值由生产常量代入**判据 B 的解析式**在测试内算出（不硬编码数值）。
  > **注意：该式与 `DeriveSubSteps` 同式，故本断言只能发现"判据 B 分支被删/未生效"，
  > 不能发现判据 B 解析式本身的错误**。」

### 怀疑 3 —— T12 对同一量写了两个数：**证实（已定位两个数的来历）**

- **1.391e-3 对、1.042e-3 陈旧**。我把前向欧拉下的解析式独立导出：
  `|velocityDiff| = a·dt/(2n)`。n=3 ⇒ **1.389e-3**；n=4 ⇒ **1.042e-3**。
- **突变 A 实测**：`T12` FAIL，live 值 = **1.391E-003 m/s**（与 :26/:194 的 1.391e-3 一致）。
  而同一条断言消息里还硬编码着 `前向欧拉实测 1.042e-3` ⇒ **运行时自相矛盾**，
  且 `1.042e-3 / (a·dt/8) = 1.00032` ⇒ 1.042e-3 是 **SubSteps=4（即 a_max=5→20 的 V-2 实验配置）**
  下的值，被留在交付版（SubSteps=3）的消息里。
- **铁律 17**：`1.042e-3` 这个数字**全仓仅出现 1 处**（该断言消息），其余两处均为 1.391e-3 ⇒ 应删除/改正 :224。

### 怀疑 4 —— D-3 两条证据的固有弱点：**证实**

- 子串匹配（仅剔 `//`）：**漏报面** = 清单外容器/重排（`ToDictionary`/`ToHashSet`/`.Order`/`Parallel` 等）；
  **误报面** = 块注释、字符串字面量含 token（当前 PoolSimulator.cs **无** `/* */`、**无**代码字符串字面量 ⇒ 暂不误报）。
- 字面量正证据 `for (int i = 0; i < _balls.Length; i++)`：`++i`/`i += 1` 等**语义等价**写法 ⇒ **假失败**（脆）。
  判定：这是**可接受的"脆"但有代价**——它拦"写法"多于拦"顺序"，且不作反证；
  宜改为"正则匹配 `for` 循环 + 断言行内含 `i++|++i|i += 1`"或直接断言"迭代序来自数组下标"的结构（更好）。
- "同进程两模拟器逐位一致"能证明/不能证明：**只能**证明"同迭代序下的确定性函数"；
  **不能**证明"遍历序只由下标决定"（需源码断言），也**不能**证明跨进程/跨平台。作者 doc 自认**到位**，
  我**独立同意**，并补充跨进程（字符串哈希种子）这一维度。

### 怀疑 5 —— T13a 越界上界：**上界推导成立，但判别力弱（证实团队担心）**

- **上界推导成立**：检查每子步末跑，上一被检子步在台侧（s≤0）⇒ 本子步越界量 s_now ≤ v·Δ = **5.5556e-3 m**。
  边界情形：本档 a=0、无接触 ⇒ 子步内速度恒定、不跨多子步 ⇒ 上界取得到。T13a 实测 4.9377 mm（88.9%）。
- **判别力（团队要求的数）**：把检查改成**每定长步末（粗 3×）**：
  越界仍发生在 k=126（**126 = 3×42**，粗网格落点与细网格重合）⇒ 上界断言**不 FAIL**。
  **突变 B1 实测**：T13a 仍 **Passed**，越界量逐位 4.9377 mm。
  **突变 B2**（每 4 子步，k 跳到 128）⇒ FAIL（**16.05 mm > 5.5556 mm**，与我预测 16.0476 mm 吻合）。
  ⇒ 断言**非空转**，但对 3× 粗化**恰无判别力**（相位对齐）。数值：v·dt_sub=5.5556 mm、v·dt=**16.667 mm**。
- `AreEqual(1, PocketProximityEvents)`：**冻结确只计一次**（`CheckPocketProximity` 在 `_frozen` 时提前 return，
  且 `Step()` 对冻结球 `continue`）⇒ 恒为 1。**会重复计数**的实现：不提前 return / 冻结后仍调检查 / `_frozen` 写反。
