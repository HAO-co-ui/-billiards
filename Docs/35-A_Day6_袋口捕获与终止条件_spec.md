### 0.3 本轮最重的一条：`captureRadius` **不是**"到袋心的距离阈值（含法向）"，而是**开口内"容一球"的横向偏移上限**

> ⚠ **用词澄清（`D6-REV-02` `M2`）**：`captureRadius` **仍然是一个半径**（3-D 中是"允许球心所在圆盘"的半径；
> 2-D 退化为袋喉面内的**半宽**）。**被否定的是"它 = `|C − tc|`（含法向分量）的距离阈值"这个读法**，
> **不是**"它是个半径"。

排期把 `captureRadius` 写成"用 `captureRadius = 0.03074`"，容易被读成"球心到袋心距离（**含法向**）< 0.03074 才算进袋"。
**这个读法有一处致命**：

1. **`|C − tc|` 含法向分量** ⇒ 快球（8 m/s，单子步位移 22.222 mm）在**越界那一子步末**，
   `|C − tc|` 已可超 `captureRadius` ⇒ **正中进袋的球被判"未捕获"**（假阴性）。

⇒ 本 spec 定下：**横向偏移 ρ = 球心在"袋喉平面内"的偏移**（`ρ = |dot(C − tc, td)|`，`td ⟂ tn`），
**不含法向分量** ⇒ **对越界量鲁棒**。

> **⚠ 与上一条重解释相互独立的第二件事：窗口存在**（`D6-REV-02` `M2`：**两者须分开陈述**）。
> `openingRadius = 0.061317 < 袋喉半宽 = 0.067562`（侧袋）/ `0.068098`（角袋）
> ⇒ 存在 **ρ ∈ (captureRadius, 袋喉半宽 − r] 的窗口**（侧袋宽 **8.25 mm**、角袋宽 **8.78 mm**），
> 球能穿袋喉、却**不满足** `captureRadius` ⇒ **既不落袋、又不被袋角挡住 ⇒ 静默离台**（§1.4 实测）。
> **该窗口在"两种读法下都存在"** —— 它只源于"开口窄于袋喉"，**与"ρ 的定义"无关**（先前把两者并列陈述易生误解，现分开）。
> ⇒ 窗口球作**一等风险**（§9 `R-S`）；归属**已裁定 (a) 冻结 + 计数**（§13 `Q-1`，**用户裁定**），**不静默继续积分**。

> **两处既有独立佐证（`D6-REV-02` `M5`，本 spec 此前未引用，现补）**：
> ① `Assets/_Project/Scripts/Runtime/Table/TableConfig.cs:152`（`Pocket` doc 注释）已写明
> 「`captureRadius` 已扣除球半径与 2 mm 余量，**单靠半径不足以判定进袋**」；
> ② `Assets/_Project/Scripts/Editor/TableImport/TableIntegrityValidator.cs:288/292` 以
> `const float margin = 0.002f;` + `derived = p.openingRadius - PoolConstants.BallRadius - margin;`
> **逐袋校验**该派生关系（DAT 族）。
> ⇒ 这两处**不是本 spec 的产物**，而是既有代码中的独立佐证 ⇒ 重解释更站得住。

### 2.2 捕获判据的精确几何（本轮核心）

**定义**（全部为规范二维物理平面，米；真源 = `Pocket`）：

```
给定球心 C、袋 p：
    tn  = p.throatNormal                      # 单位，指向网内
    tc  = p.throatCenter
    td  = (−tn.y, tn.x)                       # 面内横向单位向量（⟂ tn）

    越界量   s  = dot(C − tc, tn)             # > 0 = 已过喉平面、在进网侧
    横向偏移 ρ  = |dot(C − tc, td)|           # ★ 面内偏移，不含法向分量
```

**判据（写死，供实现与测试共用同一口径）**：

| 谓词 | 定义 | 语义 |
| --- | --- | --- |
| `Crossed(p)` | `s > 0` | 球心已穿过袋喉、朝网方向（**必要**，来自 `captureNote` 的操作条款） |
| `WithinOpening(p)` | `ρ ≤ p.captureRadius` | 整球落在**内投影片刻**内（留 2 mm 余量，来自 `captureNote` 的半径条款） |
| **`Captured(p)`** | `Crossed(p) ∧ WithinOpening(p)` | **正常落袋** |
| `JawCrossing(p)` | `Crossed(p) ∧ ¬WithinOpening(p)` | **擦袋角越界**（窗口球，§1.4；**一等风险** `R-S`） |

> **为什么 ρ 用"面内偏移"而不是 `|C − tc|`**（写死，防 §0.3 错误 1）：
> 判据在**子步末**求值（沿用内核既有姿势），此时球可能已越界 `v·dt_sub`（8 m/s ⇒ 22.222 mm）。
> `ρ` 在"沿法向直行"时**恒定**（不随越界量增长）⇒ 鲁棒；
> `|C − tc|` 含法向分量 ⇒ 越界越多、值越大 ⇒ **正中进袋的球在越界那一子步被判"未捕获"**。
> ⇒ **`ρ` 是"开口内"的正确测度；`|C − tc|` 不是。** 该点由 §5 `T31` 专门守（用 8 m/s 发射使两者可分）。

**求值时机（沿用内核，不改）**：每子步末、逐球、逐袋。**不引入**"球心穿过瞬时"的 TOI —— 因 `ρ` 对越界鲁棒，
子步末求值已足够（且避免新增一条时间轴）。

| **新增 `PocketJawCrossingCount`** | 窗口球计数（`Crossed ∧ ¬WithinOpening`）—— **`R-S` 的可观测量**（§四-3：新可观测量必须"可观测"，不靠间接推断） |
| **冻结（离台）** | **两类都冻结** ⇒ **保持"越喉平面即不再积分"的不变量**（不静默逃逸） |

**一致性不变量（等值，双边）**：
```
PocketProximityEvents == CapturedBallCount + PocketJawCrossingCount
```
⇒ 任何"多算/少算"都会打破等值 ⇒ 直接暴露（§5 `T35`）。

> **为什么不把 `PocketProximityEvents` 直接改名为"捕获"**：Day 4 的 `T13a/T13b/T13c` 已把它的**语义**
> （"越喉平面即冻结"）钉进已入库证据；**改名 = 作废既有语义锚**。⇒ **保留旧名 + 新增两个具名计数**。

### 2.4 窗口球的处置（`R-S`）—— **不静默**；归属**已裁定 (a)**（**用户裁定**，见 §13 `Q-1`）

**决定（最终口径，不放宽、不静默）**：
- 窗口球 `JawCrossing` **照旧冻结（离台）** —— **保持"越喉平面即不再积分"**（否则静默逃逸）。
- 它是**独立可观测量** `PocketJawCrossingCount`；**受控瞄准用例断言其为 0**（"擦袋口不落"要求不落袋的球**根本没越过喉平面**）；**开球族只设上界 `≤ 球数`**（`SP-1`：真开球会斜擦袋口）。
- **归属 = (a) 冻结 + 计数**（**用户已裁定**）：暂不把窗口球"算落袋"、也不补袋角几何使其弹回、也不收紧/放宽 `captureRadius`。
  `§13 Q-1` 的 (b)/(c) 备选保留为**将来翻案的候选**，并附**受影响判据清单**。

**为什么选"冻结"而不是"弹回"**：
- "弹回"需要**新几何/新法向**（窗口处**没有段**，§1.4 实测最近段距离 > r）⇒ 属**新增物理**，超出本轮"袋口捕获"范围，且无人守；
- "冻结"**复用既有不变量**（越喉平面 ⇒ 离台），**物理上自洽**（球确已穿过喉口进入网区），**且可被计数观测**。
- ⇒ 最终口径 = 冻结 + 计数（法向 `a`）。

### 2.5 终止判定：**两个不同层**，不得合并（排期第 3 条）

**现状（内核既有，两层之一）**：

| 机制 | 落点 | 取值 | 作用域 | 职责 |
| --- | --- | --- | --- | --- |
| `StoppedSpeedEpsilon` | `PoolSimulator` | 1e-6 m/s | **每球、每子步** | **数值终止**：把近零速度**置零并退出事件循环**，防 TOI 空转（R-C 修复） |
| "连续两次零时间推进即停" | `PoolSimulator` | `earliest ≤ ToiTimeEpsilon` ×2 | **每子步** | **数值终止**：球楔死在凹角时结束该子步 |

**Day 6 新增（第二层）**：

| 机制 | 落点 | 取值 | 作用域 | 职责 |
| --- | --- | --- | --- | --- |
| `RestSpeedThreshold` + `RestStableFrames` | `PoolSimulator` | 1e-3 m/s × 8 帧（**待裁定**） | **每球、每 `Step()`** | **游戏级静止声明**：`本杆结束` 的可判定信号 |

**定义**：
```
每球：若 speed_i ≤ RestSpeedThreshold 连续 RestStableFrames 个 Step() ⇒ 该球视为静止
TableAtRest ⟺ 全部球静止或已冻结（离台）
ConsecutiveRestFrameCount：当前"全员静止"的连续帧数（诊断，供双边断言）
```

**为什么必须分两层（排期"避免永远在微抖"的真实含义）**：
- 本轮 `rollingDeceleration = 0` ⇒ **球不因摩擦减速**，只靠库边/球-球碰撞几何衰减；
- 一旦速度落到 `(1e-6, 1e-3]` 区间，`StoppedSpeedEpsilon` **不触发**（它只认 ≤1e-6）
  ⇒ 球以 **0.5 mm/s 永远"爬行"** ⇒ 没有游戏级静止信号；
- ⇒ **游戏级阈值必须高于数值阈值**：`StoppedSpeedEpsilon (1e-6) < RestSpeedThreshold (1e-3)`。

**单点声明（回答排期的"是否重复？若是，谁单点？"）**：
- 两者**语义不同**（数值终止 vs 游戏静止）⇒ **不是同一不变量的两处实现**，**不构成铁律 16 违规**；
- 但**必须在同一类内、且判据断言次序** `StoppedSpeedEpsilon < RestSpeedThreshold`（防有人把二者取值搞反/合并）；
- **`TableAtRest` 的求值不得再实现一遍速度判据**（不得在 `CheckPocketProximity` 之类处顺手判"静止"）。

> **⚠ "是否置零" —— 本轮已定（`Q-3`）**：`TableAtRest` **只声明**（暴露谓词 + 计数），
> **不强行置零速度** —— 因为"强行置零"会**改变物理**（0.5 mm/s 的球被停）。
> 阈值 `1e-3 m/s` / `8` 帧为 **`乙-系数选定`**，**Day 7 复核：维持（扫描未推翻）**（§13.1）。

### 2.6 袋角行为：**复用 76 段袋角侧壁**，不新增弧段原语（排期第 2 条）

### 3.2 API 增量（最小面）

```
PoolSimulator
    + public int CapturedBallCount { get; }        // 正常落袋（Crossed ∧ WithinOpening）
    + public int PocketJawCrossingCount { get; }   // 窗口球（Crossed ∧ ¬WithinOpening）
    + public bool TableAtRest { get; }             // 游戏级静止谓词
    + public int ConsecutiveRestFrameCount { get; } // 当前"全员静止"连续帧数（诊断）
    + public int CapturedPocketIndex(int ballIndex) // 该球落入哪袋；未捕获返回 -1（供断言"哪一袋"）

PoolSimulator 常量
    + public const float RestSpeedThreshold = 1e-3f;   // 游戏静止阈值（乙-系数选定）
    + public const int   RestStableFrames   = 8;      // 连续静止帧数（乙-系数选定）
```

**三个计数的定义（写死）—— ⚠ 各自独立累加，等式是"待验证的结论"而非"定义"（`D6-REV-01` `R-A`）**：

> **`PocketProximityEvents`、`CapturedBallCount`、`PocketJawCrossingCount` 三者必须各自独立累加**：
>  · `PocketProximityEvents` 在「**越喉平面**（`s > 0`）」分支**递增**（**不得**由另两者相加得到）；
>  · `CapturedBallCount` 在「**`ρ ≤ captureRadius`**」分类分支**递增**；
>  · `PocketJawCrossingCount` 在「**`ρ > captureRadius`**」分类分支**递增**；
>  · 计数对象 = "球 × 袋 × 次"；同一球对同一袋只在其**首次越界**计 1；由 `ResetDiagnostics()` 归零。
>
> **「同一处单点判定」（§3.3 契约 1）≠「同一处相加」** —— 单点指**判定位置唯一**，
> 不指"用一个变量当另两个的和"。若实现直接以**相加**方式求 `PocketProximityEvents`，
> 则 §5 `T35` 的等值式**恒真**（对"设计本身错"完全盲）⇒ **本条是 `T35` 判别力的前提**。
> ⇒ 等式 `PocketProximityEvents == CapturedBallCount + PocketJawCrossingCount` 是**待 `T35` 验证的结论**，
> **不得**被写进实现当作"公理"。

**为什么不新增"接触时刻 API"**：`ρ` 判据在**子步末**求值即可（§2.2），**不需要**接触绝对时刻 ⇒ 沿用"测试不新增读取 API"的收敛（Day 5 §3.2 同族）。

### 3.3 契约（在内核 I/II 契约之上追加）

1. **捕获判据单点**：`s = dot(C − tc, tn)` 与 `ρ = |dot(C − tc, td)|` **只在 `CheckPocketProximity` 一处**求值；
   任何其他函数（如测试辅助、校验器）若需"是否越界"，**必须复用同一判据实现**，不得各自重写（铁律 16）。
   > **⚠ 与 `R-A` 的边界**：**"单点判定" ≠ "同一处相加"**。三者（`PocketProximityEvents` /
   > `CapturedBallCount` / `PocketJawCrossingCount`）**必须各自独立累加**（见 §3.2）；
   > 单点只约束"判定位置唯一"，**不**授权用"一变量 = 另两者之和"来省略独立计数。
2. **冻结不变量不变**：任何球心越喉平面（`s > 0`，**不论是否 `WithinOpening`**）⇒ **该球离台（冻结、停止积分）**。
3. **确定性**：冻结写入按球索引升序；捕获分支**不得**引入无序容器（`D-3`）。
4. **终止**：`RestSpeedThreshold > StoppedSpeedEpsilon`（判据断言）；`TableAtRest` 不得重实现速度判据。
5. **不引 PhysX**：`Rigidbody`/`Collider`/`UnityEngine.PhysicsModule` 一律不得出现（`D4-PHY-01` / 汇编级守卫）。

## 4. 求解过程 spec

### 4.1 子步末的袋口判定（替换 `CheckPocketProximity` 的函数体，保持单点）

```
对球 i（仅未被冻结者），逐袋 p（索引升序）：
    s = dot(C_i − tc_p, tn_p)
    if s <= 0:  continue                    # 未越界
    ρ = |dot(C_i − tc_p, td_p)|             # td_p = (−tn_p.y, tn_p.x)
    PocketProximityEvents++                 # 越界事件；★独立累加，不得由另两计数相加得到
    if ρ <= captureRadius_p:
        CapturedBallCount++                 # 正常落袋；★独立累加
        capturedPocket[i] = p
    else:
        PocketJawCrossingCount++            # 窗口球（R-S）；★独立累加
    冻结球 i（velocity = 0, _frozen[i] = true）   # 不变量：越界即离台
    break                                    # 一球只入一袋（首袋优先，袋索引升序 ⇒ 确定）
```

> **⚠ 归属规则（`SP-4`：**已知设计属性**，必须知悉）**：**归属按袋索引序取最小** ——
> 若一球同时越两个袋的平面，或**相邻袋喉平面在几何上重叠**，**该规则决定归属**（确定、可复现）。
> 把它写成"已知属性"是为了避免将来把"球从 A 袋口进去却归给 B"误当成 bug。
> 由 §5 `T36`（合成双袋）覆盖；其初版曾暴露"一球先越**非目标袋**的无限平面而被截获"，故 `T36` 的合成几何取**法向相反**的两个袋。

### 4.2 终止判定（新增，独立于袋口路径）

```
每 `Step()` 末（在全部子步之后）：
    全员静止 = true
    for i（球索引升序）:
        if 球 i 已冻结:  continue
        if speed_i > RestSpeedThreshold:  全员静止 = false;  break
    ConsecutiveRestFrameCount = 全员静止 ? (ConsecutiveRestFrameCount + 1) : 0
    TableAtRest = ConsecutiveRestFrameCount >= RestStableFrames
```

> **不置零速度**（本轮定，`Q-3`）：`TableAtRest` 是**声明**；**不强行置零速度**（避免改变物理）。

### 4.3 不变量（沿用内核两组划分，本轮扩到袋口与终止）

**组 ①：模型内自洽（必须精确成立）**

| 不变量 | 断言 |
| --- | --- |
| 越界即离台 | 球心 `s > 0` ⇒ 末速 `== 0` 且后续 `Step()` 位置**逐位不变** |
| 捕获归类完备 | `PocketProximityEvents == CapturedBallCount + PocketJawCrossingCount` |
| 捕获在开口内 | `Captured ⇒ ρ ≤ captureRadius`（逐袋） |
| 静止次序 | `StoppedSpeedEpsilon < RestSpeedThreshold` |

**组 ②：模型 vs 真值（解析/几何）**

| 量 | 甲类来源 |
| --- | --- |
| 捕获几何 | §2.2 判据（`s`、`ρ` 由 `(C, tc, tn, captureRadius)` 解析） |
| 袋角偏折 | 镜面反射律（段法向取 `normalize(C − Q)`） |
| 窗口宽 | `(袋喉半宽 − r) − captureRadius`（§1.3） |

### T30 袋角偏折（排期第 2 条）

**T30a 合成袋角段（解析，镜面律）**：合成表，单段 `a=(0,0)`、`b=(0, 0.4)`（一条"袋角面"），

  取 `e=0.9, μ=0.8`（**都非 1**）⇒ `v_out·n̂ = 1.8`、`v_out·t̂ = 0`。
- **能测出**：法向取错、$e/μ$ 未应用、`μ` 污染法向（Day 4 T1 同族，本处确认**袋角段走同一条解算路径**）。

**T30b 合成斜撞单段（镜面律 —— 把 `e` 与 `μ` **同时**钉住）**：合成表 = 1 条**水平**"袋角面"段

- **期望（甲类，镜面律）**：`v_n = −2`、`v_t = (1, 0)` ⇒ **`v_out = (μ·1, −e·v_n) = (0.8, 1.8)`**。
- 断言：`v_out ≈ (0.8, 1.8)`（分量容差 1e-4）、`TotalContactCount > 0`、`EnergyGainViolations == 0`。
- **⚠ 为什么用合成斜撞而非真实角袋（`SP-3` 裁定）**：本档测的是 **反射律**（法向独立乘 `e`、切向独立乘 `μ`），
  **不是"真实袋角几何"**；真实角袋擦射会让球**楔入并每子步重复解算直至停下**（实测 `|v| → 0`）⇒
  "弹回后仍在运动"对真实角袋**不成立**。**真实角袋由 `T28b` 覆盖**（不捕获 / 不越界 / `contact > 0` / 不升能）。
- **能测出**：法向取错、`e`/`μ` 未应用、`μ` 污染法向（本处确认**袋角段走同一条解算路径**）。
  **只钉 `e` 的用例挡不住 `μ` 写错** ⇒ 本档**同时**钉两者（适用范围 = 单段镜面律；盲带 = 折线接缝与真实角袋楔入，见 `Q-4`/`R-V`/`R-Z`）。
- **出处**：**甲**（镜面反射律闭式）。

### T31 `captureRadius` 的双边判别（**本轮 `captureRadius` 的判别力来源**）

### T32 确定性（覆盖袋口路径，排期单测之一）

> **⚠ 构造原则（同时解 `S1` 与 `M4`）**：让**唯一可能发生段接触的球只有"擦射袋角"那一颗**
> （白球直入侧袋 ⇒ 0 段接触；滚动球居中 ⇒ 0 段接触）⇒ **任何段接触必是袋角接触** ⇒
> 段接触计数即可**指认擦射球**（无需新增逐段/逐球 API，`M4` 的诉求由此满足）。

**T32a 合成单段（接触数可解析 ⇒ 用等值断言）**：合成表 = **1 条竖直"袋角面"段 + 1 个袋**；两球：
白球朝袋直入（0 段接触）、另一球正撞该段后反射且**反射路径清空**（不再接触）。
- 断言：`CapturedBallCount == 1`；`PocketProximityEvents == 1`；**`TotalContactCount == 1`（等值）**；双跑**逐位一致**。
- **能测出**：**计数虚增**（一次接触被重复解算 ⇒ `TotalContactCount` 由 1 涨到数十/数百，而单边 `>0` 永远通过，`S1`）；冻结写入顺序。

**T32b 真实表（混合场景）**：白球朝一侧袋**直入**（捕获、0 段接触）+ 一球朝角袋袋角**擦射**
（偏折、**不再接触**）+ 一球**居中滚动**（0 段接触）。跑 `Step() × 300`。
> **⚠ 选点须落档（`D3`）**：擦角球的**选点由实施方确定**（我未给保证"擦后不再接触"的解析构造）；
> 实施方**必须记录实际选点**（**段索引 + 起点 + 速度**）并写入证据，否则本用例**不可复现**。
- 断言（**双边**）：
  - `CapturedBallCount == 1`（等值）；
  - `PocketProximityEvents == 1`（等值：**仅**捕获球越喉平面；擦角球不得越）；
  - `PocketJawCrossingCount == 0`（上界）；
  - **`TotalContactCount ∈ [1, 3000]`**（下界 = 非空转；上界为**量级界**）；
  - 逐球 `position`/`velocity` **逐位一致**（`R` 格式）。
- **上界口径（`SP-2` 裁定；乙-系数选定）**：擦角球会**楔入袋角并每子步重复解算**（本工程 `R12` 家族：
  "贴库 / 贴角静止球的每子步触发，**已知且可接受**"）⇒ 接触数**随步数增长** —— **实测本场景 `TotalContactCount = 798`**。
  ⇒ 本档上界取 **3000（量级界）**，只拦"量级失控"；**严格的接触数等值由 `T32a`（`== 1`，合成单段、可解析）承担**。
  **实施方须把实测值写进 `§7.1` 证据 JSON**（字段 `t32bTotalContactCount`）。
  ⚠ **`798`（本用例）/ `5064`（15 球满堆）这两个数量级本身是 Day 7 应盯的性能 / 手感点**（见 §9 `R-Z`）。
- **能测出**：捕获 / 冻结写入顺序不确定、`ρ` 判据依赖遍历顺序、引入字典 / 并行；**量级失控**。
- **盲带**：① 源码**禁用清单不充分**（"没出现这些词" ≠ "确定性已证明"）⇒ 逐位一致是主证据，清单只是结构性补充（两互补，都不可删）；
  ② `3000` 是**量级界**、**不拦小幅漂移**（该档由 `T32a` 的等值补）。

- **出处**：**乙 + 结构**（等值/区间为**选定**的工程上界；逐位一致为非解析判据）。

**排布（`A2`：唯一化，消除第二实现）**：
- **单点生成**：把 `PhysicsTestDrive.RackPositions` **参数化**为 `RackPositions(footSpot, rackBallCount)`；`T34` / `T37` / `D5-PHY-01` **共用同一函数**（铁律 16）。
  默认 `rackBallCount = 3` ⇒ 与现行 4 球摆放**逐位不变**（`D5-PHY-01` 数值不变）。
- **显式生成式（唯一定义，行/列符号写死）**：

  ```
  s      = 2·ballRadius + 2e-4          # 球间距（与既有口径一致）
  row    = s·(√3/2)                     # 行距
  apex   = (−0.30, 0)                   # 顶点（保持既有取位；朝 +x 面向白球）
  pos[0] = footSpot                     # 白球
  idx = 1
  for r in 0..R:                        # R = 最小使 R(R+1)/2 ≥ rackBallCount
      for k in r down to 0:             # ★降序 —— 与既有 4 球字面同序（见下方兼容闸门）
          if idx > rackBallCount: break
          pos[idx++] = apex + (−r·row, (k − r/2)·s)   # y 关于 0 对称
  ```

  ⇒ 15 球 = 行 `r = 0..4`（1+2+3+4+5）；**与 `T34` 的 4 球（行 `r = 0..1`）同式**。
  ⚠ **选点由实现按上式唯一确定；若实施方另作调整，须记录实际排布（球位清单）**（与 `D3` 同源要求）。
- **⚠ 向后兼容闸门（必须断言，`C1`）**：`RackPositions(footSpot, 3)` **必须逐位等于**旧 4 球字面（**含顺序**）：
  `[footSpot, (−0.30, 0), (−0.30 − row, +half), (−0.30 − row, −half)]`，其中 `half = s/2`。
  **代入自证**：`r=0, k=0 ⇒ y = (0 − 0)·s = 0`；`r=1, k=1 ⇒ y = (1 − 0.5)·s = +half`；`r=1, k=0 ⇒ y = (0 − 0.5)·s = −half`
  ⇒ `pos[1/2/3] = (−0.30, 0) / (−0.30 − row, +half) / (−0.30 − row, −half)`，与旧字面**逐位一致**
