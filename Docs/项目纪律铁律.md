## 容差策略（两类不可混用）

- **数据集 ↔ 数据集**：索引对齐，**1e-5 m**。

## 验收与证据的铁律

1. **永远不要在替换证据产出之前删除最后的已知良好证据。** 先跑出新的并确认成功，**然后**才清理旧的；
   或改名保留。**删除也是写操作**。Day 2 后果：`day2-verification.json` 一度完全缺失，
   没人能回答"上次校验通过是什么时候、多少项通过"。
2. **「写了 N 项检查」≠「运行并观察到 N 项通过」** —— 报告只允许写后者。
   （Day 2：复核方 6 项测试因编译不过 CS0136，在修复前**从未跑起来过**。）
3. **任何否定性结论必须用第二种独立方法复核，且检索空间必须完备。**
   - Day 2 实例：主理人用 `python -c` 内嵌正则 grep `rail:` 得 0 处，误报"字段被静默丢弃"，
     实际 82 处（真因：shell 破坏 `\s`/`\S`，findall 静默返回空）⇒ **含正则的 python 一律写成文件再执行**。
   - **⚠️ 2026-10-13 追加（我本人第三次犯同族错误）**：我 grep 了 `Tests/` 得 0 命中，
     就下结论「**本工程第一架构铁律没有任何守卫**」。实际守卫**有三层**
     （`BilliardsProjectSetup.cs:202-214` 层隔离 / `SCN-04` @ `BilliardsProjectVerifier.cs:208-236` /
     `SCN-06` @ `MaterialVisualValidator.cs:301-309`）—— **两层就在我没查的 `Scripts/Editor/` 里**。
   - ⇒ **规则加强**：**不得用片面检索支撑全称否定命题。**
     「在 X 范围内查不到」只能支持「在 X 范围内查不到」，**不能支持「不存在」**。
     **全称否定命题必须显式给出检索空间的定义，并证明该空间完备。**
   - ⇒ 同族：`quality-lead` 的审计**重复了我这个错误**（它 scope 在 `Tests/` + `Runtime/`）。
     **错误会通过任务描述传染** —— 下发否定性论断时要标注其检索范围。
4. **不得以删除检查作为让套件变绿的手段。** 容差被误用时，纠正**推导依据**而保留检查。
   更有效：**把实测值本身写进检查输出**，而非只输出 PASS/FAIL —— 阈值只拦大错，记录实测值才看得见渐变漂移。
5. **派发复核之前必须先冻结被复核物。**（Day 2：先派复核、后下修正指令 ⇒ 复核对象在复核中移动，校验项 29→31、测试 35→37。）
6. **锚点指纹必须在「冻结已确认」之后取。**（Day 2：12:08 取指纹，工程侧随后又改 2 个文件 ⇒ 锚点表 2 项已过期。）
7. **关于状态的断言必须带时刻/修订。** 工作区或 HEAD 的观察**只能**支持"在 T 时刻我看到 X"，
   **不能**支持"X 属于修订 R"。
   - **7a「内容存在于修订 R」** → `git show R:<path>` 即可。
   - **7b「内容自 R 起存在 / 由 R 引入」** → 用 pickaxe，**先明确问的是哪个问题**：
     「历史上**首次**出现于哪个修订」取**最早**命中；「**当前修订中的**该内容由谁引入」取
     **内容仍存在于当前修订**的**最新**命中。**必带 `--follow`**（否则改名前的引入会漏，
     最早命中会落在改名提交上）。**「删后重现」必须另行处理**（`-S` 报的是出现次数变化，删除也算命中；
     演练 `c1引入→c3删除→c4重现`，答案按问题分别是 c1 或 c4）。
   - 父提交对照**不足以消歧**（删后重现时 `c4^` 不含该串、根提交无父，两者都会"通过"）。
   - 本会话同一失败模式**三次**：锚点取早于冻结确认；先采纳解释后要求检验；
     用 HEAD 观察推断"§5.5 属于哪个修订"并把复核方的**正确**告警误判为快照过期。
     ⇒ 三次都是**用一个时刻未言明的快照去描述跨时刻的状态**。
8. **不要用 `git add -A` 提交**（会把队友在途改动扫进自己的提交，套上不描述它们的提交信息；
   Day 2 实例：名为"追加 §十三"的提交实含 41 文件）。**用显式路径。**
8b. **提交前自查「当前是否处于协作窗口内、会影响到谁」。**
   **复核窗口期内禁止提交（含主理人自己）**；确需提交先告知复核方并给新锚点。
   主理人同一天两次栽在这条（目录级 add 扫入在途工作；承诺"核验期间不再提交"后又提交 MEMORY.md）。
   根因：提交动作只看"我要提什么"，没看"**谁在用当前状态**"。
9. **容差若来自"对误差成因的解释"，该解释本身必须先被证伪检验过。**
   Day 2 实例：「轮廓近似残差」解释被证伪（结论成立但依据换过两次）——
   第一版依据（"端点→最近面点=0"）**证据真空**（整个 footprint 内面点距离都为 0，**台面正中也是 0**）；
   第二版有效（**端点→最近边距 = 0.0000~0.0001 mm**）。⇒ 0.2613 mm 是"最近顶点"度量的**采样下限**。
   ⇒ **加强：证伪证据本身也必须检验"它能否为假"。一个恒真的证据等于没有证据。**
10. **生成物守卫的强度 = 生成器读取的东西。**
    生成器读源 → 可查源指纹，但**逻辑漂移抓不到**（版本戳未变则判 up-to-date）⇒ 守卫须覆盖**生成器逻辑指纹**。
    生成器什么都不读（纯转写）→ **指纹类检查为空转，必然假 PASS** ⇒ 只能**重跑真正的检查器**逐字段比对。
    正确不变量：**提交记录中的值 == 用已提交的检查器对已提交的资产重新算出的值。**
    （Day 2：主理人对 `d2t02b-crosscheck.json` 做"重跑转写脚本+diff"得 PASS，而该脚本唯一一次
    `open()` 是**写**文件、不读任何东西 ⇒ PASS 无意义。）
11. **诊断与处方必须分别验证 —— 诊断正确不能推断出处方正确。**
    复核方**正确**诊断"0.2613 mm 是顶点采样下限"并证伪了旧解释，但由此推出的处方
    （"换成面点度量、阈值收到 1e-4 m"）**不成立** —— 任何"到面"度量对**沿面滑动**天然盲
    （实测 1 mm 与 20 mm 沿面位移双双漏检，且 20 mm 的度量值**小于** 2 mm 的 ⇒ 非单调）。
    ⇒ 正确结构是**双层**（必要条件层 + 敏感性层）；**换度量不能替代敏感性层**。
    ⇒ **不可达的验收条款必然制造假通过** —— 发现条款不可达时**先怀疑条款**，而不是加压实现方。
    ⇒ **纪律**：处方写进实施令前先要求**注入式反例验证**（"这个改动会不会让检查变弱/变成恒真？"）。
    主理人**三次**把未验证的论断写进指令，第三次是被下级在动手前拦下的
    ⇒ **「先验证再实施」必须制度化，不能靠自觉。**
12. **「到最近特征」类度量天生非单调、有盲带，不能用作可靠检出判据。**
    实测（顶点间距 2.5~5.5 mm）：δ ≈ [1.95, 2.9] mm 存在约 0.95 mm 宽盲带，最坏处度量仅 0.0859 mm ⇒ 期间任何位移判 PASS。

    | 度量 | 底噪 | 盲区 |
    | --- | --- | --- |
    | 到**面点** | 0.0000 mm | 对**面内任意方向**滑动全盲（恒 0） |
    | 到**边** | 0.0002 mm | 对**沿边方向**滑动全盲；同样有振荡盲带 |
    | 到**顶点** | 0.2613 mm | 无方向性盲区，但**有周期性盲带** |

    ⇒ **可靠检出的唯一形态是「索引对齐的对应关系」**（`CMP-03` 之所以可靠正因如此）。
    ⇒ 以"最近"作对应关系的检查**必须显式声明盲带区间**，且**不得被引用为检出保证**。
    ⇒ 盲带是**端点自身轨迹的属性**（不是单点注入的巧合）；推算中任何"斜率/系数/比例"必须先被实测锚定。
13. **冻结必须以「提交」为基准，锚点必须是提交级。不要用工作区指纹。**
    工作区**无原子快照、无 git 保护** —— 取指纹与下发之间有窗口，对象随时可改而锚点看上去仍"有效"。
    本会话**两次**"复核对象在复核中移动"皆源于此。
    ⇒ **主判据（不依赖 HEAD）**：`git diff <指名提交> -- <冻结路径集合>` → 必须为空。
    这**同时蕴含**"blob 一致"与"工作区干净"。`HEAD` 与 blob 哈希**仅作附注**（HEAD 是可变指针，用它判会假阳性）。
    ⇒ **为什么不能用 HEAD**：Unity 编译/运行读**工作区**，不是 HEAD ⇒ 会"验证的是提交、跑的是工作区"。
    ⇒ 复核方第一步必须**先验这条**，不符即停止上报。
    ⇒ ⚠️ **核验必须用 git 级命令，不要用文件 SHA256**（`.gitattributes` 为 `* text=auto eol=lf`，
    工作区可能是 CRLF，SHA256 与 blob 对不上）。**blob 哈希是 SHA-1 git 对象哈希。**
    ⇒ 被复核方宣布"冻结"后必须**真停手**（**写入即违反**）；复核方发现锚点移动时
    **立即停止、不自适配、不按任一版本出结论、上报**。
    ⇒ 附带：`Materials/**` 重新生成**逐字节幂等**；但 `Main.unity`（代码生成物）**不幂等**
    （fileID 每次重排、160/160 行差异）⇒ **对手工编辑不会在重跑中幸存**，且每次重跑产生 git 噪音。
14. **宣布冻结前必须确认「无在途规格变更」并取得实施方「已停手」确认。**
    主理人错误：仍有规格变更在途时就宣布冻结，且锚点取自实施方报告而非冻结时实测。
    ⇒ **冻结握手三步**：① 主理人声明"规格冻结，不再变更"；② 实施方确认已实现全部规格并停手；
    ③ 主理人在**静止点**取指纹并提交，锚点取自该提交。
    ⇒ **判断"是否违反冻结"必须看它是否已收到指令，不能只看 mtime** —— 消息只在**回合边界**投递，
    长回合执行中的写入**不构成违反**。**主理人也不得在冻结期内再发规格变更 —— 冻结是双向承诺。**
15. **必须区分「检查不足」与「信息缺失」—— 后者不能靠加检查解决。**
    多数缺陷属**检查不足**（假通过、无判别力、空转守卫、恒真证据、不可达条款），解药是"把检查设计对"。
    但**信息在源头就不存在**时，任何新增检查都无法消除该不确定性（Day 3：桌体法线贴图是**可平铺细节图、
    无几何真值** ⇒ 不存在"测量其真实切线约定"的途径 ⇒ "不翻转"只是**声明级推断**）。
    ⇒ 处置只有两种：① **获取新信息**；② **明确标注为"声明级"**并写清"未做什么实测"。**禁止写成"已确认"。**
16. **同一不变量在多处入口的前置条件必须单点实现 —— 否则必然"改一处漏一处"。**
    本工程已**三次**遇到同形态的"口径分叉"：① 校验器与测试各有一份几何实现（R1e 用共享类收敛）；
    ② Day2 与 Day3 两校验器各自重建产物（R2 分别修）；③ `ValidateInteractive`（菜单）与
    `ValidateFromCommandLine`（命令行）各写一份前置条件（R2 只修了命令行）。
    - **⚠️ 2026-10-13 第四次**：`SCN-04`（Day1）与 `SCN-06`（Day3）是同口径**两份独立实现**，

### Day 4 spec 的三条硬结论（必须保留）

1. **「82 段库边」是误读** —— 实为 **6 段直库 + 76 段袋角侧壁**（中位段长 13.958 mm，76/82 短于球直径）。

3. **积分格式是致命项** —— `position += velocity * remaining` 是**前向欧拉**，误差 `½·v₀·Δ_sub`
   （**与减速度无关**）**线性累积**；v₀=8 m/s、SubSteps=3 时 **11.11 mm = 38.9% 球半径**，
   **加大子步数救不回来**（需 n≥3333）。必须**端点精确** `p += (v − ½aΔ·v̂)·Δ`，
   且 **TOI 必须共用同一均速**。实测：修正后自由飞行误差恒为 0。
